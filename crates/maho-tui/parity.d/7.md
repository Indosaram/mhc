Golden parity (tools/golden, generated from pinned senpi):

- `tui-screen-main-basic` (30x8), `tui-screen-main-multiline` (24x5, includes a 30x6 -> 24x5 resize), `tui-screen-alt-basic` (30x6, wheel + resize + exit) and `tui-screen-alt-preserve` (24x6): each `.ansi` fixture is the byte stream senpi's renderer wrote for the case's steps and the `.<cols>x<rows>.json` fixture is the screen senpi's VirtualTerminal shows afterwards. `tests/tui_screen_golden.rs` replays both and compares byte-for-byte.
- The 100 -> 60 column resize case compares the resized screen against a from-scratch render at 60 columns, and against the 100-column viewport to prove no cell right of column 60 survives.

Rust-side notes:

- `Component::virtual_line_count` / `Component::render_virtual_row` (src/tui.rs) exist only because senpi's "paints only clipped rows from very large scroll content" relies on JavaScript sparse arrays; a component that declares a virtual count is never materialized by the layout engine, which reads just the painted rows.
- `ScrollView::new` returns `Rc<RefCell<ScrollView>>` (senpi's `ScrollView` is always used through a reference and its layout node carries `state: this`); the node's state handle is stored with `Rc::new_cyclic`.
- senpi's transient-scrollbar `setTimeout` becomes `ScrollView::hide_due_at_ms` + `fire_hide_timer_if_due`, polled by the host loop (same pattern as todo 6's `run_due_timers`).
- examples/chat-simple.rs ports test/chat-simple.ts. senpi's `editor.onSubmit` mutates `tui.children` synchronously; the port queues the submitted value and applies it after the input dispatch borrow is released, because a Rust closure cannot take a second `RefCell` borrow of the screen.

## Deviations from the pinned source (all inside this todo's files)

- `ask-user-question.ts`, `ask-user-question-keys.ts`, `first-time-setup.ts`, `grok/*`: senpi reads a
  module-global `theme`; these ports take the active `Theme` as an explicit parameter.
- `ask-user-countdown.ts` and the `setInterval` drivers of `armin.ts`/`daxnuts.ts`: the crate has no
  event loop, so timers advance from explicit host ticks (`tick(now_ms)` / `tick()`), the todo-31
  convention. `armin.ts`/`daxnuts.ts` take their effect/seed explicitly instead of `Math.random`.
- `grok/chrome.ts`: four types the seam names are owned by other todos and are not available in this
  lane (`CustomEditor` and `InteractiveSession` from todo 35, `ToolExecutionPresentation` from todo
  32, `ReadonlyFooterDataProvider` from todo 35). The grok-owned classes are ported; those seams use
  in-crate equivalents (`Rc<RefCell<dyn Component>>` base editor, `GrokFooterSession`, a `&'static
  str` presentation tag, a rows count). Todo 35 wires the real types in.
- `earendil-announcement.ts` and `first-time-setup.ts` compose `DynamicBorder` (todo 32) and
  `buildNoticeBox` (`core/extensions/notice/`, outside this crate's source root); both render the
  identical output privately until those modules exist.
- `tips/*`: `keyHint`/`rawKeyHint`/`keyText` live in `components/keybinding-hints.ts` (todo 33), so
  `ask-user-answer-key.ts` carries private equivalents that todo 33 will replace.

Coverage: 45 deterministic Rust tests across the twelve files. The renderer corpus compares call and
result renders byte-for-byte against pinned senpi at 80 columns; the card, extra, transcript,
boundary, custom and overflow corpora compare full component renders byte-for-byte at 40 and 80
columns; the descriptor and fallback corpora compare the produced structures and strings directly.
Two comparisons strip ANSI on one line each because the crate's todo 31 `highlight_code` classifies
`echo` differently from senpi's highlight.js — a `highlight_code` fidelity gap rather than a
component one.

A todo 31 file, `src/theme/theme.rs`, diverges from senpi on empty input: senpi's
`bold`/`italic`/`underline`/`strikethrough`/`inverse` are chalk calls and return `""` unchanged
for an empty string, while this crate's `Theme` wraps it in escape codes. It is reachable only
through an empty label (for example a tool named `""`), so no todo 32 fixture depends on it; the
case is left out of the call-fallback corpus rather than pinning the divergence. `src/theme/`
belongs to todo 31, so this fragment records the finding instead of editing it.

One necessary deviation: senpi slices a provider-native body at 2000 UTF-16 code units, which can
land between a surrogate pair and leave a lone surrogate. Rust strings are valid UTF-8 and JSON
cannot carry a lone surrogate, so `assistant_render_descriptors.rs` slices the same 2000 units and
decodes them with `from_utf16_lossy`, yielding the U+FFFD a terminal renders for that lone
surrogate. The fixture records the same character, so the observable output still matches.
Everything else, including the borders, prompts, output bodies and status lines around those lines,
is compared byte-for-byte.

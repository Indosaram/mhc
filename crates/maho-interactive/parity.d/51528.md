Notes (senpi v2026.10.27-2):
- render-signature: omitted array tails and object keys are folded entry by entry (25d048c15c, #4415);
  the pinned signatures in tests/golden/components32-tools.json were regenerated from the tag's TS.
  JSON values carry no `toJSON`, so the `serializerKey`, hole and getter cases have no Rust analogue.
- extension-selector: `answerSettled` fencing (63a7ffeb3f) reuses the existing `disposed` flag.
- pause-footer: `interrupted-run` hold records render the Interrupted footer (8c5b96cb9b, 2821fd4bf4).
- lifecycle-status / interactive-mode: the footer projects `session_lifecycle` (fae4cb50ec, 3ffffa7369);
  host-owned status keys survive /reload (25acb02f29); ephemeral dialogs skip the host bracket
  (a644802688); `session_recovered` is a warning (a37de3fcb3).
- session-control-*: the terminal control endpoint (base + senpi#3246/#4267 delta). The mode is not
  `Send` and the endpoint serves on tokio tasks, so `src/session_control_surface.rs` (no TS file) carries
  senpi's `sessionControlContext()` closures: the mode publishes what they read every frame and runs what
  they ask on its next frame. senpi's lazy `import()` of the endpoint has no Rust analogue (nothing runs
  until a registration). Its never-attached `tui-null` writer connection is unnecessary: records no
  attached connection takes come back from the fanout and are dropped. Endpoint tests:
  tests/session_control_endpoint.rs (Unix socket, real session).
- interactive-mode (row 20): each extension binding registers the terminal UI as its MCP MRTR presentation
  (`register_mcp_mrtr_presentation`) under a per-binding lifetime aborted on rebind and at dispose,
  pre-aborted during shutdown. Under `--mcp-presenter-enforcement` the binding's private forms go
  through the injected `InteractiveModeOptions::local_mcp_presenter` factory (row 21; the CLI passes
  `maho_cli::cli::mcp_local_presenter::register_local_mcp_presenter`, which lives in maho-cli with its test
  tests/mcp_local_presenter.rs because maho-ext-mcp already depends on this crate): the terminal enrolls as the
  `local_tui` principal of its own `maho_rpc` `McpPresenterAuthority`, forms queue FIFO per binding
  with the remaining deadline, a failed collector settles its form, and an ephemeral selector/input
  answer skips `admit_human_answer` (the presenter admits once); the selector marks the form presented
  (`ExtensionUiDialogOptions::presented`) after the frame that paints it.
- session-control-host: `start_extension_binding` installs the host with
  `AgentSession::set_control_endpoint_host` (senpi `setControlEndpointHost`), so the generation's
  `pi.session.registerControlEndpoint` serves through the terminal; dispose uninstalls it.
- session-control-endpoint: each wake pass emits `session_control_wake` (reason, reasons, delivery_ids)
  into the session's extensions through `AgentSession::emit_session_control_wake` before the drain.
- session-control-endpoint (senpi#3246): a failing drain pass reports `control endpoint drain failed`
  once per distinct reason until a pass succeeds; `SessionControlDrain` resolves to a `Result`, whose
  `Err` is senpi's rejected drain (a panic fails the pass too) (tests/session_control_endpoint.rs,
  ported from 3246-rpc-drain-notice-cap).

- session-control-rpc-commands: `abort` and `get_effect_status` run the host's `run_abort` /
  `run_get_effect_status` over `maho_rpc::agent_effect_session::AgentEffectSession` (routed per
  endpoint, its event forwarding released at dispose). Core's queue carries no `clientMessageId` or
  per-input revision and model changes carry no `effectId`; the adapter documents what that leaves out.
Rewired to what exists: the `emitted` edge is a session-control delivery's `message_end` (core has no `ExternalAdmission::on_emitted`).

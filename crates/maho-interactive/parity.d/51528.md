Notes (senpi v2026.10.27-2):
- render-signature: omitted array tails and object keys are folded entry by entry (25d048c15c, #4415);
  the pinned signatures in tests/golden/components32-tools.json were regenerated from the tag's TS.
  JSON values carry no `toJSON`, so the `serializerKey`, hole and getter cases have no Rust analogue.
- extension-selector: `answerSettled` fencing (63a7ffeb3f) reuses the existing `disposed` flag.
- pause-footer: `interrupted-run` hold records render the Interrupted footer (8c5b96cb9b, 2821fd4bf4).
- lifecycle-status / interactive-mode: the footer projects `session_lifecycle` (fae4cb50ec, 3ffffa7369);
  host-owned status keys survive /reload (25acb02f29); ephemeral dialogs skip the host bracket
  (a644802688); `session_recovered` is a warning (a37de3fcb3).
- session-control-*: the terminal control endpoint (base + senpi#3246/#4267 delta). The mode is not
  `Send` and the endpoint serves on tokio tasks, so `src/session_control_surface.rs` (no TS file) carries
  senpi's `sessionControlContext()` closures: the mode publishes what they read every frame and runs what
  they ask on its next frame. senpi's lazy `import()` of the endpoint has no Rust analogue (nothing runs
  until a registration). Its never-attached `tui-null` writer connection is unnecessary: records no
  attached connection takes come back from the fanout and are dropped. Endpoint tests:
  tests/session_control_endpoint.rs (Unix socket, real session).
- interactive-mode (row 20): each extension binding registers the terminal UI as its MCP MRTR presentation
  (`register_mcp_mrtr_presentation`) under a per-binding lifetime aborted on rebind and at dispose,
  pre-aborted during shutdown. `registerLocalMcpPresenter` (private forms under
  `--mcp-presenter-enforcement`) waits for rpc `mcp-presenter-authority`; until then maho-cli refuses
  `--mcp-presenter-enforcement` on the TUI path instead of ignoring it.
- session-control-endpoint (senpi#3246): a failing drain pass reports `control endpoint drain failed`
  once per distinct reason until a pass succeeds; mhc's drain returns no error, so a panicking drain is
  the failed pass (tests/session_control_endpoint.rs, ported from 3246-rpc-drain-notice-cap).

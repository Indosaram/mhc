# Parity closure: syntax highlight token classes
| TS path | Rust path | TS tests | Rust tests | status |
|---|---|---:|---:|---|
| theme/theme.ts | src/theme/highlight.rs | 0 | 0 | partial |
| packages/coding-agent/src/utils/syntax-highlight.ts | src/theme/highlight.rs | 0 | 0 | done |

Grammars now come from `two-face` (bat's syntect set), which carries TypeScript, Kotlin, Swift,
Dart, Groovy, Nix and the rest of senpi's 20 eagerly registered highlight.js languages. Only those
names and their highlight.js aliases are highlighted; anything else (including json/yaml/toml,
which senpi does not register eagerly) renders as `mdCodeBlock`, as in senpi.

TextMate scopes are mapped onto the highlight.js classes of `buildCliHighlightTheme`: keyword,
built_in/type (`syntaxType`), literal/number, string, comment, title/class (`syntaxFunction`),
params/attr/variable, `meta` (`muted`), operator (only for grammars whose highlight.js definition
emits it: Swift, Nix), punctuation (Rust `->`, tag delimiters). This is `partial` because two
different tokenizers cannot agree token-for-token; the Rust `let` binding post-pass stays because
the TextMate Rust grammar has no scope for it. `addition`/`deletion` are unreachable upstream too
(diff is not an eager language).

Ported from senpi 59d58cee59: every queued input carries a session-unique `queuedId` (`q_<n>`, `_mintQueuedId`) and
a `revision` (1 when queued, +1 per edit); `dequeue_queued_input` / `edit_queued_input` change one input in the
visible lists, the post-compaction deferred lists and the agent's native queue alike, refuse a stale
`expected_revision` as `conflict` (probing the native queue so a delivered input still answers `already_delivered`),
and remember the last 256 delivered ids. `change_queued_input` routes an input in durable custody through
`SessionPendingInputs::change` first. `get_pending_inputs` answers `SessionPendingInputs::snapshot`.

ADAPTATION: upstream addresses the queued message object by identity; Rust messages are values, so the agent's
`change_queued_message(queue, message, occurrence, next)` names the queue and which equal message it means.

GAP (not ported here): upstream `_enqueueQueuedInput` admits an input that carries a `clientMessageId` into the
pending-input store and installs the store's queue port on the agent, publishing `pending_input_update`. Core's
steer/follow-up entry points carry no client id, so no input enters durable custody: `get_pending_inputs` answers
an empty `inputs` list and `not_admitted` for every id. The store is created per session (`SessionPendingInputs`,
journal over the session file) so the read and the change path are live once admission lands.

Tests ported (src/agent_session.rs): regressions/1971-queued-input-dequeue-edit.test.ts (3 harness cases; the
durable reopen case needs admission), regressions/3459-queued-input-expected-revision.test.ts (5 cases), and the
no-custody `get_pending_inputs` snapshot.

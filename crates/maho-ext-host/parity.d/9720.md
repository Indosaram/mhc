maho-core AgentSession now calls `set_event_handler_budget` with the
`extensionEventHandlerWarnMs` / `extensionEventHandlerTimeoutMs` settings
(SettingsManager::get_extension_event_handler_warn_ms / _timeout_ms), a stall listener that logs
`extension_handler_stalled` and shows the warn-stage notice (report_extension_handler_stall), and a turn
scope bumped at prompt admission (senpi `_promptAgent`: `prompt_with_readiness` and
`trigger_custom_message_turn_with`, not continuations); `AgentSession::release_held_extension_handlers`
releases the current turn's held waits (senpi agent-session.ts `_applyExtensionBindings`,
`releaseHeldExtensionHandlers`). An abort the run does not honour within `TURN_DEADLINE_GRACE_MS` releases
the turn's held waits (senpi `_waitForIdleAfterAbort`): the Esc abort (`AgentSession::abort`, including
one that joined an open agent_end boundary) and the deadline abort (`DeadlineSessionOwner for
AgentSession`, `abortTurnForDeadline` = `_abortActiveAgentAndRetry("system")` then the idle wait).

The deadline path is live only since the core-122 follow-up: before it, no `AgentDeadlineTracker` was
constructed outside turn_deadline.rs tests, so the deadline abort never ran in production. AgentSession now
owns one (senpi agent-session.ts constructor), built right after the session with a weak owner and limits
read from `turn_inactivity_ms` / `turn_max_runtime_ms` at each arm. It is armed at prompt admission (the
same two `_promptAgent` sites that bump the turn scope), renewed by tool execution start/update/end,
cleared by person input (`_beginPersonInput`), and disarmed when the run settles idle and on dispose.
`record_deadline_stop` captures the stop for the run's lifecycle before the write (senpi
`lifecycleBinding.deadlineStopped`) and marks it `persisted: false` when the write is refused
(`deadlineStopWriteFailed`); the session lifecycle's `lastStop` then reports cause `deadline`.

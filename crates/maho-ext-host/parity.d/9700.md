## handler-budget.ts / senpi#3650 (new in this fragment)

`runner.ts` runs the queued lifecycle events (`agent_start`, `agent_end`, `agent_settled`,
`turn_start`, `message_start`, `message_update`, `message_end`, `tool_execution_*`) and the boundary
events (`turn_end`, `agent_before_settle`) under a host budget set with `setEventHandlerBudget`, and
the turn deadline calls `releaseHeldHandlers(turn)`. None of that existed natively, so a hung
lifecycle handler could hold the session forever. Ported:

- `src/handler_budget.rs`: `ExtensionHandlerBudget`, stall stages, `HeldHandlerWaits` (turn-scoped
  release), `run_budgeted_handler`, the default 60 s warn / 1 200 s cap constants.
- `src/runner.rs`: `set_event_handler_budget`, `release_held_handlers`, once-per-emission budget
  resolution with a once-only invalid-setting diagnostic falling back to the defaults,
  `report_stopped_handler` (`handler timed out after Nms` / `handler released by the turn deadline`),
  applied in `emit` and `emit_message_end`. The budget wiring is carried across `recreate_with_context`.

Native difference: JavaScript keeps a stopped handler running detached and reports a later
rejection as a `late_failure` stall. A native handler future borrows the emission's event and
context, so the host drops it at the cap/release; there is no late outcome to report.

Tests: `src/handler_budget.rs` (HeldHandlerWaits turn release - port of the
`3650-extension-handler-budget.test.ts` "releases only the waits of the given turn" case - plus
timeout, release and timely-settle cases) and `tests/runner.rs`
(`lifecycle_handler_past_its_budget_is_reported_and_skipped`,
`turn_deadline_releases_a_held_lifecycle_handler`,
`invalid_handler_budget_keeps_awaiting_handlers_in_order`).

## Remaining host binding (why runner.rs stays partial)

maho-core's AgentSession does not yet call `set_event_handler_budget` with the
`extensionEventHandlerWarnMs`/`extensionEventHandlerTimeoutMs` settings, a stall logger
(`extension_handler_stalled`), or `release_held_handlers` from its turn deadline / Esc path
(senpi `agent-session.ts:4350,4356,9594`). Those files belong to other lanes; until bound, the runner
keeps senpi's own pre-bind default (`UNBOUNDED_HANDLER_BUDGET`). `emitBoundary` has no native
caller either (no `turn_end`/`agent_before_settle` dispatch through a boundary builder), so those two
events are budgeted only through `emit`.

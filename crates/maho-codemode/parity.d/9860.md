## Cross-Crate & Asset Notes

- Non-`.ts` JS/shared assets (`assets/kernels/js/*.js`, `assets/kernels/shared/path-identity.*`, `skill/bun/*`) are tracked with exact SHA-256 checksums in `assets/UPSTREAM.json` and embedded via `src/kernels/shared/runtime_asset.rs`.
- Cross-crate hooks awaiting workspace crates outside `crates/maho-codemode`:
  - `maho_ext_api::ToolInfo.eval_only` (falls back to `exposure == Eval && !active`)
  - `maho_tools::definition::ToolDefinition.full_prompt_guidelines` (`EvalPromptParts.full_prompt_guidelines` populated; `ToolDefinition` receives `prompt_guidelines`)
  - `maho_ext_api::AgentToolResult.is_error` vs `details["isError"]` (`tool_result_marshal::tool_result_is_error` retains `details["isError"]` check alongside `eval_tool::tool_result`)
  - `CodemodeExtensionOptions.is_loop_remote` (exposed via `register_with_loop_remote`, defaulting to `false` for existing `maho-cli` callers)
  - `terminal.killGuard`, `inheritedEnv`, `withCredentialProxy`, and `attestSessionSpawn` optional hooks wired and defaulting to `None`/`false`
  - `PermissionToolHost` runtime enforcement runs in the Bun worker via `assets/kernels/js/interpose*.js` + `permission-*.{js,mjs}` + HTTP `/permission_check` (matching the external Bun subprocess relay architecture of `maho-codemode`, while `src/kernels/js/permission_{host,sessions,worker_frames}.rs` hold the Rust authority state machine).

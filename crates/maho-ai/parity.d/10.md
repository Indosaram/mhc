# maho-ai (todo 10 — openai completions and responses / azure-openai-responses)

Plan todo 10 ("maho-ai [OI] wire APIs: completions, responses, azure responses") is the union of
three sub nodes integrated in this lane: `sub/ai-replay` (the shared recorded-SSE replay harness and
the local axum mock server), `sub/10-completions` (`api/openai-completions.ts` and its 151 TS cases)
and `sub/10-responses` (the Responses share: `api/openai-responses.ts`,
`api/openai-responses-shared.ts`, `api/azure-openai-responses.ts` and both `.lazy.ts` wrappers).

## openai-responses — source

`api/openai-responses.ts` (919 lines) is ported to `src/api/openai_responses.rs`: the
`stream`/`streamSimple` state machine, `buildParams` (reasoning ladder and the `summary: "auto"`
default, cache key/retention/options, service tier, max_output_tokens clamp, tool_choice, reserved
keys), header building with session affinity, service-tier cost multipliers, and the
`scheduleSessionWebSocketExpiry` session-cache half of the WebSocket transport (see below).

`api/openai-responses-shared.ts` (1136 lines) is ported to `src/api/openai_responses_shared.rs`:
`convertResponsesMessages` (function/custom/grammar items, namespaces, foreign-signature and
foreign-tool-call-id normalization, message ids, configuration updates), `convertResponsesTools`,
`processResponsesStream` over an SSE body (`process_responses_stream`) and over a parsed event
sequence (`process_responses_events`), image-generation reconciliation, terminal-event finalization
and `getDoneReason`.

`api/azure-openai-responses.ts` (350 lines) is ported to `src/api/azure_openai_responses.rs`:
Azure base-URL normalization, deployment/resource resolution, params and headers.

Both `.lazy.ts` wrappers are ported 1:1 as `ProviderStreams` modules behind `lazy_api`.

### WebSocket transport: documented partial

senpi's Responses adapter can stream over a WebSocket when the runtime provides one; maho-ai
declares no WebSocket client, so `connect_websocket_error` reports senpi's own "WebSocket transport
is not available in this runtime" and `stream` falls back to SSE exactly as senpi does when
`globalThis.WebSocket` is missing. The session-cache half of that path —
`CachedWebSocket`/`is_websocket_reusable`/`CachedWebSocketConnection`/`cache_websocket_session`/
`schedule_session_websocket_expiry` — is ported and covered by
`test/openai-responses-websocket-expiry.test.ts` 1:1. The socket dial/handshake/liveness half stays
unported with the transport it belongs to.

## Golden replay

`tools/golden/cases/ai-replay-openai-{completions,responses}-*.json` are replayed through the pinned
senpi `stream()` by `tools/golden/ai-replay.mjs`, which writes
`crates/maho-ai/tests/golden/replay/<case>.json`. The Rust side replays the same bytes through a
local axum mock server (`crates/maho-ai/tests/support/mock_server.rs`) and compares the event
sequence with `assert_matches_golden`. Evidence: `.omo/evidence/task-10-replay.json` (happy path,
two tool calls, senpi and maho event arrays plus the diff) and `.omo/evidence/task-10-eof.txt`
(mid-stream close → typed error, no panic).

## Details
In pinned upstream `packages/omo-senpi/src/components/task/index.ts:55-83`, task engine initialization resolves config via:
```ts
loadConfig = options.loadConfig ?? loadSenpiOmoConfig;
const loaded = loadConfig({ cwd });
composeTaskEngine({ omoConfig: loaded.config, cwd, ... })
```

In native `crates/maho-cli/src/cli/default_extensions.rs`, line 159 previously attempted to load task configuration from `parent.with_settings_manager(|settings| settings.get_value("omo")...)`, inspecting the `"omo"` key in `settings.json` rather than resolving `omo.jsonc` (project and home user configs). Consequently, agent definitions (such as `agents.explore.model`) configured in `~/.maho/omo.jsonc` or workspace `omo.jsonc` were never supplied to the native task planner, producing `plan_error 'No available model for agent "explore" (attempted none)'`.

Switching line 159 to `super::task_runners::resolved_omo_config(&ctx.cwd, &environment)` directly invokes `maho_omo_config_resolution::load_senpi_omo_config` with the active workspace cwd and execution environment, ensuring 1:1 behavioral parity with upstream config resolution.

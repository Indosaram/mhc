N/A reasons for the counts above:

- `test/suite/regressions/1781-main-lazy-modes.test.ts` asserts the duplicated sentinel literal
  equals `INTERNAL_SUPERVISOR_FLAG` and that the route stays out of the ordinary launch graph. The
  Rust case pins the equality and the launcher's emission; the lazy-import half has no native
  counterpart (there is no deferred module graph in a compiled binary).
- The CLI's session mounting is exercised through the same `mount_agent_session_runtime` path the
  app-server and print modes use (lane 38 rows), so this fragment does not restate those cases. The
  multi-session entry cases live in `tests/multi_session_entry.rs`: the CLI configuration built from
  `--mode rpc --multi-session --listen`, the per-open profile mapping (`a_profile_session_path_and_durable_id_reach_the_session_manager`
  for a fresh session with a durable id, `a_profile_session_path_opens_that_session_with_the_profile_cwd`
  for an explicit `sessionPath`), and `a_cli_built_host_answers_the_protocol_and_exits_on_its_empty_window`.
  The whole chain (ensure -> supervisor -> host child) is driven by the authored QA driver
  `tools/latest-omo-host-qa.mjs`. The registered skill surface and the `omo-git-bash` MCP subprocess
  are driven by `tools/latest-omo-skill-qa.mjs` and `tools/latest-omo-git-bash-qa.mjs`; none of the
  three has an upstream unit test counterpart (they exercise real subprocesses, not a library
  export), so their rows carry no Rust test count.
- `CliRuntimeRequest.session_profile` now carries session kind/context from the host open
  profile. The classic launch computes its profile through `session_profile()` and passes it
  to both the extension loader and the SDK session factory. The two native regressions above
  are authored, not executed; registered subprocess propagation remains unverified.
- `omo-senpi/components/memory/kibitzer/sidecar.ts` (the resident in-process child) maps to
  `src/cli/kibitzer_child.rs`. The upstream file's unit tests
  (`sidecar.test.ts`, `sidecar-*.test.ts`) exercise the memory-side lease/deadline/backoff
  state machine owned by `maho-omo-memory`, not the CLI child adapter; this fragment's row
  therefore carries no Rust test count. The adapter's five member-scoped tool closures
  (`kibitzer/tools/{read,grep,session-read,memory,nudge}.ts`) and the persona
  (`memory-core` `recall/kibitzer-persona.md`) are not yet ported by the memory owner, so the
  spawner builds a child with exactly the closures it is handed and never a builtin
  passthrough. This is a named source input, not a proxy pass.

Notes:

- cross-project-session: senpi's async `confirm` is a blocking callback here. `cli/runtime.rs`
  (drift-owned) still prints its own copy of the non-interactive fork text and does not call this
  module yet.
- session-opening and process-identity take their probes as arguments. They are not called from
  `main.rs`/`runtime.rs` (drift-owned) yet.
- continue-moved takes core `listMovedSessions` as an injected lister (core `moved-sessions.ts` has
  no Rust port yet); its prompt half is `confirm_same_repository_rebind` in `cross_project_session.rs`.
- host-session-command runs over `maho_rpc::host_session_runner` (ported on sync5152/L-rpc-server;
  this module compiles only once that branch is merged). `deferred_commands::dispatch_host_command`
  routes `host session` to it; `main.rs` (senpi-interactive) still calls `host_command` directly and
  must call `dispatch_host_command` instead. `--rpc-key-root` is resolved and handed to the runner,
  but the Rust runner has no per-request key root, so only the `SENPI_RPC_KEY_ROOT`/agent-dir
  default applies.
- experimental/micro runs over `maho_agent::harness::pico3`. sessions/api/tools are complete.
  models.rs ports `createPicoModels` (the pico3 `Models` impl over `ModelRuntime`), `toAiContext`
  and `readModelsView`. `cwd` is held but not forwarded (no `cwd` on maho-ai request options), and
  an aborted error under an aborted context ends the stream instead of throwing.
  tools.rs keeps the tool memo in-call, because pico3's `ToolApi` is `!Send` and the harness
  invocation must be `Send + Sync`. main.ts and runtime.ts (rows 90/92) are requeued to
  senpi-interactive, and tui.ts (row 95) is the alt-screen host over `openMicro`, so it waits on runtime.ts.
- client-tui-chat and mini/tui/view.ts render the snapshot as plain text lines. The rich
  AssistantMessage/ToolExecution/LoginDialog/ModelSelector components are not mounted in the mini
  host loop: that is the senpi-interactive component wiring, and the snapshot projection is tested.
  Upstream ships no test file for any mini/* or client-tui-chat module, so the mini rows close on
  the existing tests/mini_*.rs suites.
- mini models-service: accounts now come from each provider's auth methods (OAuth and/or API key,
  API-key `interactive` = has_login), sorted with ICU collation; a label suppresses `source`
  (upstream's `??`/`===` precedence); refresh goes through the shared
  `model_catalog_refresh::refresh_model_catalogs` with the 15 s CATALOG_REFRESH_TIMEOUT_MS.
- cli/app-server-command.ts and core/shared-host-policy.ts do not exist at the pin (removed upstream in
  cfd8449096 and 58a08c18fa, both ancestors of 903b8336); they are not part of this crate's source root.
- utils/zip.ts is named `zip_archive` so it does not shadow the `zip` crate.

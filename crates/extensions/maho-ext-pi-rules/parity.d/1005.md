## UTF-16 unit domain (todo 1005, revision 2)

The shared `picomatch` module now maps the pattern through `utils::js_units` before tokenizing
(`Parser::new` and `parse::fastpaths`), the same mapping `Compiled::is_match` applies to the
haystack, and `js_regex_expression` drops a `\` written before a unit character. Pinned picomatch
measures branches with `String#length` (UTF-16 code units) in `analyzeRepeatedExtglob`,
`getStarExtglobSequenceChars` and `hasRepeatedCharPrefixOverlap`, so astral branches inside
`+(...)`/`*(...)` bodies no longer collapse to a flat single-unit `[...]*` class. Both crate copies
of `src/rules/picomatch/*.rs` received the identical edit; no hash is claimed by this authoring
pass.

## JS escape semantics and `expandRange` sort (todo 1005, revision 3)

The shared `picomatch` module now translates every backslash escape to the JS (Annex B, no `u`
flag) meaning instead of passing it through: `regex-syntax` disagrees with JS on `\a` (bell vs
literal `a`), `\z`/`\A` (text anchors vs literal `z`/`A`), `\<`/`\>` (word-boundary assertions vs
literal `<`/`>`), `\U` (hex vs literal `U`), `\p`/`\P` (Unicode classes vs literal `p`/`P` without
the `u` flag) and `\0`..`\9` (unsupported backreferences vs legacy octal / identity), and rejects
any other escaped ASCII letter. Shared class/control escapes and `\xHH` are kept verbatim,
`\uHHHH` becomes `\u{HHHH}`, a JS `LegacyOctalEscapeSequence` (`\0`..`\377`) and `\cX` become
`\x{..}`, and every JS identity escape becomes the literal character. Because the pinned
`normalizeGlobs` rewrites every `\` to `/` before a glob reaches picomatch, this behavior is
observable only through the grammar module; `tests/matcher.rs` drives it there and `grammarCases`
in the source-generated corpus covers it.

`expand_range` sorts with `Array#sort`'s default comparator (UTF-16 code-unit order) rather than
Rust's scalar-value order and emits the class body in the mapped unit domain, splitting each UTF-16
unit range into its mapped pieces (`0xD800..=0xDFFF` -> `0x1D800..=0x1DFFF`); an out-of-order range
takes the pinned `escapeRegex`/`join('..')` fallback exactly as `new RegExp` throwing does, and a
body carrying a JS class escape keeps the pinned template plus the Rust validity check.

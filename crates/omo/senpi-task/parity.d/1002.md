## Behaviour and selected native correction
- `team_status { teamRunId }` returns the `aggregateStatus` projection (teamName, teamRunId, status,
  createdAt, members with unread counts, tasklist counts, shutdownRequests, concurrency, bounds,
  staleLocks) as the tool result details.
- `team_list { scope? }` joins the declared specs (`discoverTeamSpecs` + `loadTeamSpec(...).members.length`)
  with the active runs (`listActiveTeams`); a declared-only team is `not-started` with its declared member
  count; an active team with no declared spec is appended; `scope` filters both declared specs and
  appended active runs in the selected native correction.

## Divergences / notes
0. N/A exact latest scope parity: latest query.ts appends active runs regardless of scope. The
   selected registered regression requires every returned entry to match a non-all requested
   scope. Native query.rs filters appended active runs by their provenance scope; the all listing
   and declared-spec precedence remain intact. This is an explicit selected behavior deviation,
   not pinned/latest identity equivalence. Existing registered scope assertions are retained.
1. `build_lead_team_tools` publishes EIGHT tools (the six upstream lead tools + `team_status` +
   `team_list`). Upstream senpi-task publishes six and omo-opencode registers the two query tools in its
   own plugin tool registry; the native port has no separate plugin registry layer, so the contract
   routes them through `build_lead_team_tools`. The ported `allowlist.test.ts`
   (`src/tools/team/allowlist_tests.rs`) therefore expects the eight-name list. `is_task_or_team_family_tool`
   already classifies both (`team_` prefix), so the child-filter case is unchanged.
2. The TS tool reads `process.cwd()` for the project root; `run_team_list` keeps that source and the
   module also exposes `run_team_list_in(scope, project_root)` so tests scope deterministically.
3. `aggregateStatus`'s optional `bgMgr` concurrency probe has no native counterpart; the service reports
   the no-manager shape (`runningOnSameModel: 0`, `queuedOnSameModel: 0`, `teamRunIdSpecific` omitted),
   exactly as the TS aggregate does when no background manager is supplied (the query.test.ts case).

Notes:
- `unresponsive-close.ts` is partial. Its reattach input (`UnresponsiveReattach`) lives in the maho-cli assembly, so `HostSessionHandle` builds the close with `reattach: None`; the code carries a SAFETY-DIVERGENCE marker for this. A disconnected close is refused and retried.
- `host-session-revive.ts` is partial. Only `reconcileHostSessionOrphan` is ported. `parkHostSessionOnDaemonLoss`/`retryDeferredHostSessions` predate this sync and were absent.
- The startup groups run on scoped threads instead of `Promise.all`, under a PERF-DIVERGENCE marker in `reconcile.rs`.
- `deferred-owner-reconcile.ts` is still todo. `retryOwner`, `retryDeferredLegacyOwners` and `reconcileDeferredDeadChildren` were absent before this sync, and so was the `provisional-exit.ts` path they call. Only the v5.1.52 `reconciliationActive` stop is in scope here, and it has no loop to attach to until the module exists.
- The 30 s liveness-notice debounce is injectable (`TaskManagerOptions.liveness_notice_timer`); the child-liveness tests fire it by hand instead of waiting.
- The live-parent recovery worker cadence is injectable (`LifecycleDeps.live_parent_recovery`, default every 5 s); the reconcile-startup tests disable it so its unfenced scan cannot race the gated passes.
- `revive_workpool_task` now refuses a worker whose session is not running with `SendOutcome::Unresponsive`, as upstream `ports.revive` does through `sendToTask`; before this the workpool `unresponsive` refusal arm was unreachable.
- session-confirmed-close: the host matrix is covered by the two listing/ack tests in `session_close_proof.rs`; the lifecycle-frame and refused-retry cases are ported there against `confirm_host_session_absent`. The transport-cut case needs the maho-rpc client (cross-lane) and is covered only by the `connected()` guard test.

Notes:
- `unresponsive-close.ts` is partial. Its reattach input (`UnresponsiveReattach`) lives in the maho-cli assembly, so `HostSessionHandle` builds the close with `reattach: None`; the code carries a SAFETY-DIVERGENCE marker for this. A disconnected close is refused and retried.
- `host-session-revive.ts` is partial. Only `reconcileHostSessionOrphan` is ported. `parkHostSessionOnDaemonLoss`/`retryDeferredHostSessions` predate this sync and were absent.
- The startup groups run on scoped threads instead of `Promise.all`, under a PERF-DIVERGENCE marker in `reconcile.rs`.
- `deferred-owner-reconcile.ts` is ported. `retryOwner` stops when the pass fence goes stale (`!reconciliation_active`) as well as on `retries_stopped`. `create.rs` runs `reconcile_deferred_dead_children` inside the 9797ec726 generation fence, then starts `retry_deferred_legacy_owners`. Upstream awaits `Promise.all` there; Rust runs the retries on scoped threads, under a PERF-DIVERGENCE marker.
- The retry backoff `wait` is a separate `LifecycleDeps.host_retry_wait` (API-DIVERGENCE marker in `context.rs`) because `HostSessionRetryPolicy` stays a plain value. The default wait returns early once the lifecycle is disposed (PERF-DIVERGENCE marker in `deferred_revival.rs`).
- `deferred-revival.ts` is partial. Only the stop registry (`stop/resume/dispose_scoped_retries`, `retries_stopped`) is ported. `retryDeferredScopedChild` predates this sync and is still absent, so the same-session `rpc_detached` case of `provisional-exit-retry.test.ts` is not covered.
- The `provisional_exit` record field, its parse, and the strip on terminal/start/lost/revive are ported. The manager-side writer (`manager/provisional-exit.ts`, confirmation window) is not, so the lifecycle tests seed the exit it writes. The manager-only cases of `provisional-exit.test.ts` (write failure, early timer, task_output rendering, fallback hand-off) are not covered.
- `reclaim_orphaned_resident` now re-probes the owner pid under the record lock, as upstream b248ccb8ba does. `markLost`'s `target_gone` destroy cause has no Rust variant, so `ReconcileLost` is used; it takes the same orphan teardown path.

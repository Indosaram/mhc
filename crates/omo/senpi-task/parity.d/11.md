Notes:
- `unresponsive-close.ts` is partial. Its reattach input (`UnresponsiveReattach`) lives in the maho-cli assembly, so `HostSessionHandle` builds the close with `reattach: None`; the code carries a SAFETY-DIVERGENCE marker for this. A disconnected close is refused and retried.
- `host-session-revive.ts` is partial. Only `reconcileHostSessionOrphan` is ported. `parkHostSessionOnDaemonLoss`/`retryDeferredHostSessions` predate this sync and were absent.
- The startup groups run on scoped threads instead of `Promise.all`, under a PERF-DIVERGENCE marker in `reconcile.rs`.
- `deferred-owner-reconcile.ts` is ported. `retryOwner` stops when the pass fence goes stale (`!reconciliation_active`) as well as on `retries_stopped`. `create.rs` runs `reconcile_deferred_dead_children` inside the 9797ec726 generation fence, then starts `retry_deferred_legacy_owners`. Upstream awaits `Promise.all` there; Rust runs the retries on scoped threads, under a PERF-DIVERGENCE marker.
- The retry backoff `wait` is a separate `LifecycleDeps.host_retry_wait` (API-DIVERGENCE marker in `context.rs`) because `HostSessionRetryPolicy` stays a plain value. The default wait returns early once the lifecycle is disposed (PERF-DIVERGENCE marker in `deferred_revival.rs`).
- `deferred-revival.ts` is partial. Only the stop registry (`stop/resume/dispose_scoped_retries`, `retries_stopped`) is ported. `retryDeferredScopedChild` predates this sync and is still absent, so the same-session `rpc_detached` case of `provisional-exit-retry.test.ts` is not covered.
- The `provisional_exit` record field, its parse, and the strip on terminal/start/lost/revive are ported. The manager-side writer (`manager/provisional-exit.ts`, confirmation window) is not, so the lifecycle tests seed the exit it writes. The manager-only cases of `provisional-exit.test.ts` (write failure, early timer, task_output rendering, fallback hand-off) are not covered.
- `reclaim_orphaned_resident` now re-probes the owner pid under the record lock, as upstream b248ccb8ba does. `markLost`'s `target_gone` destroy cause has no Rust variant, so `ReconcileLost` is used; it takes the same orphan teardown path.
- The 30 s liveness-notice debounce is injectable (`TaskManagerOptions.liveness_notice_timer`); the child-liveness tests fire it by hand instead of waiting.
- The live-parent recovery worker cadence is injectable (`LifecycleDeps.live_parent_recovery`, default every 5 s); the reconcile-startup tests disable it so its unfenced scan cannot race the gated passes.
- `revive_workpool_task` now refuses a worker whose session is not running with `SendOutcome::Unresponsive`, as upstream `ports.revive` does through `sendToTask`; before this the workpool `unresponsive` refusal arm was unreachable.
- session-confirmed-close is partial. Ported: the lifecycle-frame case at `HostSessionHandle` level (`handle_liveness_tests.rs` `a_lifecycle_frame_cannot_confirm_an_overdue_session_that_remains_listed`: not exited, terminal-pending, one listing, notices `unresponsive, terminal-pending`); the transport-cut case at the fake `HostRpcClient` seam (`a_transport_cut_swallowed_by_the_engine_close_never_proves_a_retained_session_ended`), not over the real maho-rpc client; the refused-retry case against `confirm_host_session_absent`. The 12-way host matrix is covered only at `confirm_host_session_absent` level by two tests: no stalled-listing case and no manager `host_liveness` overlay assertion.
- `HostSessionHandle` now reacts to `session_closed` frames like `clientBinding.onClosed`: ignored while terminal-pending (`closingUnresponsive`), otherwise the session ends and its connection is detached (`releaseEndedSession`). Frames are not counted as liveness activity. Parking (`session_parked`, `handoff_parked`/`idle_evicted`) is left to the heartbeat under a SAFETY-DIVERGENCE marker, because the Rust manager has no parked-session listener; that row is partial.
- child-liveness: all five upstream cases are ported; `terminal_pending_bypasses_the_transient_status_debounce` advances the injected timer. The older `an_unresponsive_child_holds_sends_notifies_the_parent_and_drains_on_recovery` in the same file is the manager side of handle-liveness and is not counted here.
- Workpool revival acknowledges the worker turn only after `revive_workpool_task` answers `Revived` (upstream order), so an unresponsive or not-continuable refusal keeps the turn's queued entries and its `dispatching` delivery (`an_unresponsive_refusal_keeps_the_turns_queued_entries`).

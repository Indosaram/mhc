## Implementation details

The portable signal cancellation extends RU-01 spawn cancellation to non-Linux supported platforms without PID reuse race or blocked abort waiting on child:
- On Linux: retained owned `pidfd` cancellation via `pidfd_open` / `pidfd_send_signal`.
- On non-Linux Unix (macOS, FreeBSD, etc.): portable signal cancellation via safe POSIX `waitid(P_PID, pid, &mut info, WEXITED | WNOWAIT)` synchronization and `libc::kill`.
  - The child is waited without reap under `WNOWAIT` so that the PID is retained in zombie state by the kernel and never recycled while unreaped.
  - In `wait_without_reap()`, non-EINTR errors are propagated accurately without silent swallowing, ensuring errors do not disable abort or allow PID reuse.
  - In `exited()` and `wait_with_output()`, `wait_without_reap()` is awaited with `?` before calling `mark_reaped()` and `child.wait()`, ensuring reaping ownership and signaling guards remain strictly synchronized.
  - Intentionally before `child.wait()` reaps the process, `handle.mark_reaped()` transitions `inner.reaped = true` under mutex, guaranteeing no numeric PID is ever signaled after reaping or during kernel PID recycling.
  - Abort listeners send signals immediately via `libc::kill` without blocking on child exit or waiter threads.
- On Windows: handle-based cancellation via duplicated process `OwnedHandle` and `TerminateProcess`.
  - Windows process handles reference the underlying executive process kernel object, eliminating numeric PID reuse races.
  - On `TerminateProcess` failure with `ERROR_ACCESS_DENIED`, the process handle is checked via `WaitForSingleObject(handle, 0)`: a signaled handle (`WAIT_OBJECT_0`) authoritatively proves the process already terminated (even if its exit code was 259), returning success. If the process is still running (`WAIT_TIMEOUT`), `ERROR_ACCESS_DENIED` is propagated accurately as a real refusal rather than swallowed.
- `ProcessHandle` is exported on all supported platforms (`#[cfg(any(unix, windows))]`).
- Repeated `exited` calls preserve cached exit code. `spawn_sync` ignores signal per upstream contract.

## Currently applied regression source

The 4 Unix process tests in `tests/processes.rs` (`wait_with_output_observes_cancellation_after_child_readiness`, `signal_less_spawn_preserves_stdout_and_stderr`, `synchronous_spawn_ignores_an_aborted_signal`, `wait_with_output_retains_no_numeric_pid_signaling_after_reap`) and the 7 lifecycle regression tests in `tests/spawn_cancellation.rs` are enabled across all Unix platforms (`#[cfg(unix)]`). The obsolete off-Linux `Unsupported` error expectation in `tests/processes.rs` has been removed now that non-Linux platforms support native signal cancellation.

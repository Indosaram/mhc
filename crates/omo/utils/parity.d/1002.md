## Behaviour delta (contract for parent owner allocation; NOT fixed here)

The task forbids editing `crates/omo/utils/src/runtime/spawn.rs` (the shared-core git-bash lane
depends on the existing resolver), so the delta is returned as a contract:

1. **`SpawnOptions.signal` is absent — the one real behaviour delta.**
   - Upstream: `packages/utils/src/runtime/spawn.ts` (`SpawnOptions.signal?: AbortSignal`) forwards
     `signal` into Node's `spawn` options via `createNodeSpawnOptions`, so aborting the signal kills
     the child. `runtime-shims.test.ts:163-184` asserts `options.signal === signal`.
   - Native: `crates/omo/utils/src/runtime/spawn.rs` `SpawnOptions` has no `signal` field, and
     `build_command`/`spawn`/`spawn_sync` never observe an abort.
   - Contract for owner: add `signal: Option<AbortSignal-equivalent>` to `SpawnOptions` and wire
     cancellation into `SpawnedProcess` (e.g. a watcher that calls `Child::kill` on abort). Owner
     crate: `crates/omo/utils` (shared-core lane) — **not** this lane.
2. **`createNodeSpawnOptions` / `createNodeSpawnSyncOptions` have no named Rust counterpart.**
   Their behaviour is folded into `build_command` (stdio via `resolved_stdio`, `shell:false` is the
   Rust `Command` default, `cwd`, `env` via `env_clear().envs`, `detached` via `process_group(0)` on
   unix, `windowsHide` via `CREATE_NO_WINDOW` on windows). Equivalent except for the `signal` field
   above; the sync options have no `signal` in Node either, so the sync path has no delta.
3. **Bun branch — N/A in Rust.** The `globalThis.Bun` spawn/spawnSync path and the Bun-unavailable
   Node-fallback transpile test have no Rust runtime counterpart (documented in `parity.d/2.md`).
4. **Overload shape.** TS `spawn(options & { cmd })` vs the Rust positional
   `spawn(cmd: &[String], options: &SpawnOptions)` — the crate's documented
   "positional optional parameters became input structs" divergence, not a behaviour delta.

Notes:
- SAFETY-DIVERGENCE(omo pane-auth): upstream `createPaneAuthDirectory` exports `OPENCODE_SERVER_PASSWORD_DIR` into `process.env` and removes the directory on process exit. This crate forbids `unsafe` (`std::env::set_var`), so it returns a `PaneAuthDirectory` guard (removed on drop) and the lifecycle functions read `OPENCODE_SERVER_PASSWORD_DIR` from their injected `EnvSource`; without it the password file goes into a lazily created `PaneAuthFallbackDirectory` owned by the injected deps (`TmuxDeps::pane_auth`, team-core `TeamLayoutDeps::pane_auth`). Rust has no safe exit hook and a `static` is never dropped, so dropping the last deps clone (not process exit) removes the directory and every unconsumed password file.
- `buildPaneAuthEnvironmentArgs` fails closed: an unwritable password file returns `Err`, and each lifecycle function logs and returns failure instead of putting the password in argv.
- `build_tmux_attach_command_from` / `build_tmux_placeholder_command_from` read the `withPaneAuth("")` switch from the injected environment; the process-env variants keep the old signatures.
- New dep: `uuid` (workspace, v4) for the one-use file name (`randomUUID`).

## Notes

- `src/lib.rs` previously declared `pub mod palace {}` (an empty inline module), so the whole
  `src/palace/` tree was never compiled. It now declares `pub mod palace;`, matching the
  `commands`/`bindings` roots; the palace modules and their tests compile as part of the crate.
- `commands/memfs.ts` gained the one missing pinned case (`#given a reachable mirror #when sync
  runs #then the push is reported as successful`) so `src/commands/memfs.rs` reaches the 15 TS
  cases in `memfs.test.ts` (real `git init --bare` mirror + `file://` remote).
- `commands/people-ask.ts` carries no in-module tests; its two pinned cases run through
  `src/commands/people.rs` (`people-ask.test.ts`), which also hosts the `people.test.ts`,
  `people-gate.test.ts` and `people-selection.test.ts` cases.
- `commands/commands.test-support.ts` and `commands/people.test-support.ts` map to the
  `#[cfg(test)]` helpers `src/commands/test_support.rs` and `src/commands/people_test_support.rs`;
  `palace/palace.test-support.ts` maps to the `#[cfg(test)]` `src/palace/test_support.rs`.
- Consumer wiring for `/palace` (upstream `wiring-static.ts` calls `registerPalaceCommand`) is not
  yet present in the CLI host; that registration and the config-driven palace people resolver
  belong to the CLI integration lane, not this crate.

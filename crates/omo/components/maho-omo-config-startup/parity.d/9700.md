## Ported at pin 354bcf9

The newer omo pin added two files. Both are now native ports rather than `todo` rows.

- `metadata-launch.ts` -> `src/metadata_launch.rs`. `is_metadata_only_launch` walks argv exactly
  as senpi's parser does: an option that always takes a value consumes the next argument even when
  it looks like a flag, `--mode`/`--use-theme`/`--tui-mode`/`--list-models` only take a
  non-option value, `--print`/`-p` also accepts a `---`-prefixed message, and everything after
  `--` is message text. `--multi-session` or `--listen` answers false immediately because a
  multi-session host serves sessions whatever else it was given. `ConfigStartupComponent::argv`
  gates `register`: a metadata-only launch returns before migration and config loading.
  Six native tests cover the 11-case upstream table, which upstream itself counts as one `test.each`
  row per launch (the audit counts the table once).
- `opencode-routing-notice.ts` -> `src/opencode_routing_notice.rs`. The gap computation lives
  with the conversion machinery it reuses: `setup::opencode_models::open_code_routing_gap` builds
  the edition's raw choices overlaid by the document's `[opencode]` block, converts them with the
  same `convert_categories`/`convert_agents` the installer uses, and reports only entries the
  document does not already set in `categories`/`agents` or their `[senpi]`/`[native]` blocks.
  `open_code_routing_notice` is the one-line lead. The plan is `ReplaceTarget`, carries no sources,
  and gates on content plus the `_migrations` marker, so a config with nothing to report is left
  byte-identical. It is appended to the startup migration's plan list after the legacy plans.

### Upstream Behavior to Native Implementation Mapping

1. **Lazy First-Use Runtime Lifecycle**:
   - The desktop service, engine child, session handle, and tool execution delegates are imported and constructed on first use only (`runtime.load()`), keeping startup lightweight and leaving unused desktop sessions inert.
   - Activation changes on `handle` automatically synchronize with the host active toolset (`computer` and `computer_actions` join/leave the active set).
2. **Deterministic Status & Passive Discovery**:
   - `/computer status` reports engine state (`not started (source)`, `ready`, or diagnostic), search prelude status, yielded skill indicator, and passive permissions.
   - Unavailable hosts return clean warning without registering tools or event listeners.
   - Skill materialization and `disabled_skills` filtering resolve authentically without artificial fallback directories.
3. **Telemetry & Event Boundary**:
   - Context preservation across `session_start`, `tool_execution_start`, and slash command executions.
   - Telemetry emissions for tool activations, engine errors, OS capabilities, and tier denials.
4. **Child Relay Routing & Ancestry**:
   - `readSessionAncestry`: Native `read_session_ancestry` detects child processes via `session_context["role"]` or environment variables `OMO_SENPI_TASK_RPC_CHILD`, `OMO_SENPI_TASK_DEPTH`, and `OMO_SENPI_TASK_ROOT_SESSION_ID`.
   - `Child Extension Event Forwarding`: Emits `CHILD_PERMISSION_EVENT` (`"computer.permission_required"`).
   - `Child Relay Ingestion`: Root session relays into root permission handler and persists marker.

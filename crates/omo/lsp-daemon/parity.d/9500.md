On Windows the daemon endpoint is the `\\.\pipe\omo-lsp-<version>-<digest>` path from
paths.rs. `transport::connect` opens it with tokio's named-pipe client and retries while
every instance reports `ERROR_PIPE_BUSY`, as libuv does. `Listener::bind` creates the first
instance with `first_pipe_instance(true)`, so a second owner fails the way Node's EADDRINUSE
does. `accept` hands over the connected instance and creates the next one. `random_bytes`
uses the OS CSPRNG through getrandom. `process_alive` and `send_signal` follow libuv `uv_kill`:
access denied counts as alive (EPERM), and SIGINT, SIGQUIT, SIGKILL and SIGTERM call
TerminateProcess.

Identity helpers (`path_identity`, `directory_identity`, `is_socket`) are left as they were.
Upstream skips identity on win32 (`endpointIdentity` returns `{kind: "windows"}`, and
`ensurePrivateDirectory` returns early), and the Rust callers branch on `cfg!(windows)`
before they call these helpers. `version_reap` still defers on win32 without signalling,
which matches upstream. `src/transport_tests.rs` adds one round-trip test (bind, accept,
connect, echo) that runs over a unix socket on unix and a named pipe on Windows. No Windows
compile or test run has happened in this lane.

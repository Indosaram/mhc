# lsp-daemon parity

Rust port of `@code-yeongyu/lsp-daemon` (TypeScript, `packages/lsp-daemon`). Binary `lsp-daemon`
keeps the CLI contract: `lsp-daemon [mcp | daemon]` (default `mcp`), usage error exit 2
(`Usage: omo-lsp-daemon [mcp | daemon]`), env overrides `OMO_LSP_DAEMON_DIR`,
`OMO_LSP_DAEMON_CLI`, `OMO_LSP_DAEMON_VERSION` (CLI/VERSION must be set as a pair). IPC protocol
(`_omo` envelope, protocolVersion 1, auth -32001 / protocol -32002, `omo/ping`, `$/cancelRequest`),
state files (`daemon.lock`, `.pid`, `.auth`, `.endpoint`, `.owner`, `.sock`) and failure
result texts match the TS source. Extra native behaviour: CLI tests in `tests/cli.rs` (usage exit 2,
default `mcp`, singleton override rejection, crashed-owner reclaim + SIGTERM clean exit).

## Stale lock / ownership reclaim

- `src/lock_tests.rs::stale_lock_owned_by_dead_pid_is_reaped_and_acquired`, `garbage_lock_contents_are_reclaimed`.
- `tests/daemon_server.rs::crashed_owner_leftovers_are_reclaimed_and_auth_rotated` (dead pid lock + owner + dead socket file).
- `tests/cli.rs::daemon_subcommand_reclaims_a_crashed_owner_and_exits_cleanly_on_sigterm` (real binary).
All run under a 10s bounded timeout; none hang or panic.

## Sibling gaps

- `lsp-core::mcp` keeps its `ParseErrorPayloadReader` private, so `src/proxy.rs` carries a private
  copy to echo the offending line in `-32700` parse-error `data` (TS `JSON.parse` message parity).
- No other adapters: lsp-core (MCP handler, request context, abort, LSP manager) and mcp-stdio-core
  (stdio JSON-RPC server, parent watchdog) are used directly.

## Deliberate differences

- The daemon launcher prefers the native binary: `OMO_LSP_DAEMON_CLI` pointing at a `.js`/`.mjs`
  file is launched with `node <cli> daemon` (legacy), anything else as `<cli> daemon`. Version-reap
  attestation accepts both a node+cli.js+daemon command line and a native `lsp-daemon daemon` one.
- Parse-error `data` uses serde_json's message plus the offending text instead of V8's wording.

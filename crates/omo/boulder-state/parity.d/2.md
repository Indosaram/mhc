## Deliberate divergences

1. Corrupt state is an error, not `null`. TS `readBoulderState` swallows every failure into `null`. Rust returns
   `Result<Option<BoulderState>, BoulderStateError>`: missing file and `{}` are `Ok(None)`; unreadable file
   (`Read`), invalid JSON (`InvalidJson`), non-object root or a `works` map with non-object entries
   (`InvalidShape`) are errors. Every entry point that reads state propagates the error with `?`, where TS
   would have treated the file as absent (and e.g. `appendSessionId` returned `null`).
2. Write failures are errors. TS `writeBoulderState`/`clearBoulderState` return `false`; Rust returns
   `Result<(), BoulderStateError>` (`Write`, `Remove`). Entry points that returned `state | null` after a failed
   write now return `Err`.
3. Positional optional parameters became input structs: `createBoulderState(plan, session, agent?, worktree?)` ->
   `create_boulder_state(plan, session, &WorkOwner)`, `completeBoulder(dir, workId?, endedAt?)` ->
   `complete_boulder(dir, &CompleteBoulderInput)`, `endTaskTimer(dir, work, key, endedAt?)` ->
   `end_task_timer(dir, work, &EndTaskTimerInput)`, `normalizeSessionId(id, platform?)` ->
   `normalize_session_id(id)` + `normalize_session_id_with_platform(id, SessionPlatform)`. Defaults are unchanged.
4. `BoulderState` / `BoulderWorkState` / `TaskSessionState` are accessor views over the raw JSON object rather
   than closed structs, so unknown fields and `null`s survive exactly as the TS spread-based updates preserve them.
   JavaScript object semantics needed for identical bytes (keys set to `undefined` keep their slot; array-index keys
   enumerate first; integral floats print as integers) live in `src/js.rs`.
5. `generateWorkId` draws its 32-bit suffix from std's randomly keyed SipHash instead of `Math.random`; format and
   range (`0..0xffffffff`, 8 zero-padded hex digits) are identical.
6. `works` given as a non-empty array (TS would enumerate it by index) is rejected as `InvalidShape`; an empty array
   is treated as "no works". Neither shape is produced by any writer.
7. `findPrometheusPlans` sorts by `mtime` with `SystemTime` precision instead of `mtimeMs`.

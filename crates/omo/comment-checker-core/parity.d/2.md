## Behavioural mapping / deviations

- `SpawnProcess`/`SpawnFn` are injected as a trait plus a closure, and `ReadableStream`s become `AsyncRead` streams. `setTimeoutFn`/`clearTimeoutFn` are dropped: the timer is `tokio::time::timeout`, and tests control it with tokio's paused clock.
- On timeout, TS schedules SIGKILL after `killGraceMs`, but its `finally` clears that timer before it can fire, so only SIGTERM is ever sent. The Rust port keeps that observable behaviour: it sends SIGTERM only. `kill_grace_ms` is kept on the options for surface parity. Kill errors are swallowed, as in TS.
- TS `createRequire(...).resolve("<pkg>/package.json")` becomes a Node-style ancestor `node_modules` walk from `import_meta_url` (a `file://` URL or an absolute path), with the result canonicalized like Node's realpath. Package `exports` maps are not interpreted.
- Promise rejections from spawn or stdin writes surface as `Err(io::Error)`. Stream read errors and exit errors return the empty result, matching the TS `catch`.
- `CommentFilter`, `CommentInfo`, `PendingCall`, `FileComments`, and `FilterResult` are type-only exports in TS. They are ported as serde types with the TS field names.

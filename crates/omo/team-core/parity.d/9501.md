# 9501: Windows lock-owner liveness

| Upstream | Native | Status |
|---|---|---|
| `team-state-store/locks.ts` `isPidAlive` (`process.kill(pid, 0)`, which libuv implements on win32 through `OpenProcess`) | `team_state_store/locks.rs` `is_pid_alive` (`#[cfg(windows)]`: `OpenProcess` + `GetExitCodeProcess`) | done |

Supersedes the Windows N/A row in `9480.md`: a dead owner is now detected on Windows, so a stale lock is reclaimed once `stale_after_ms` passes instead of being held by an assumed-live owner. An `OpenProcess` failure of any kind (access denied included) counts as not alive, like unix `EPERM`: pinned `isPidAlive` (`locks.ts:95-104`) reads every `process.kill(pid, 0)` error as a dead owner (parity gap omo-team-tmux-mcp-skills-w2-02).

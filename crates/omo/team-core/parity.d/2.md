# team-core parity

Rust port of `@oh-my-opencode/team-core` (`packages/team-core`). Each module mirrors its TS directory: `team_layout_tmux`, `team_mailbox`, `team_registry`, `team_state_store`, `team_tasklist`, `team_worktree`, plus `types`, `config`, `error`, `session_client`, `member_parser`, `resolve_caller_team_lead`, `shell_quote`, and `logger`. The runtime state machine (`is_valid_transition`, `transition_runtime_state`), the mailbox reservation/ack/lease ordering, the tasklist claim rules, and the resume failure modes (stuck `creating` -> `failed`, dead lead -> `orphaned`, dead worker -> `errored`, last worker dead -> `orphaned`, stale `.delivering-*` reclaim) are ported one-to-one.

## Deviations

- `team-registry/loader.test.ts` "defaults createdAt from Date.now when omitted": the TS test stubs `Date.now`. The crate's clock override is `pub(crate)` and test-only, so `loader_defaults_created_at_from_now_when_omitted` asserts that `createdAt` falls between wall-clock readings taken before and after the load. The observable contract (a default taken from the current time) is unchanged.
- Async TS APIs are synchronous Rust functions; concurrency tests (`with_lock_serializes_concurrent_work`, the consumer-lease tests) use threads and channels in place of promise interleaving.
- Injected fs hooks (`AtomicWriteDeps`, `LockOpenErrorDeps`, `LockReleaseDeps`) stand in for the TS `deps` parameters; `platform` mirrors `process.platform`.

## Sibling gaps

- `tmux-core` does not re-export the stale-session sweep callback types, so `team_layout_tmux` declares equivalent private `Arc<dyn Fn ...>` aliases inside this crate. No sibling crate was edited.

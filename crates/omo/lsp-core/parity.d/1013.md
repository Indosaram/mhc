## Parity Notes

- Whole-document formatting workflow: `format_document_with_client` requests edits from `client.format_document`, converts LSP text edits to parsed edits, normalizes them against current file bytes via `normalize_text_edits`, computes line churn via `line_delta`, and commits changes atomically via temporary file (`.omo-format.tmp`) and atomic rename.
- Mtime preservation & no-op detection: when server returns no edits or normalized text reproduces current file bytes, `FormatDocumentResult::UNCHANGED` is returned immediately without touching the filesystem, keeping file mtimes intact.
- Capability gating: when document formatting is not advertised by the server, `FormatDocumentResult::CAPABILITY_NOT_ADVERTISED` is returned.
- Stale-edit rejection: shrinking file or out-of-bounds positions returned by server are validated against live lines by `normalize_text_edits` and rejected with explicit error message matching TypeScript behavior (`outside line`).
- Ninth tool MCP surface: format tool registered with title "LSP Format", aliases `["lsp_format"]`, schema requiring `filePath`. Nine-tool schema pinned in tool-surface tests.
- Parameter tests: JSON syntax cannot represent NaN/Infinity values directly, so JSON-level null and non-numeric representations are asserted in `parameters.rs` tests.

## API shape notes

- The TS package is async throughout; the Rust port is synchronous (blocking IO and
  `std::process`). Sequencing and observable order are preserved; the async wrapper was a
  runtime artifact, not behavior.
- `Env`/`RequestContext` become `env::Env` (owned binding trait objects) and
  `env::RequestContext<'a>` (borrowed env, cache, deferred-work sink, outbound `fetch`).
- `Response.json(stats)` is `serde_json::to_string(&DownloadStats)` with
  `rename_all = "camelCase"`; `DownloadStats` counts are `i64` so the emitted JSON matches
  the upstream integer spelling (`servedFromMirror: 9`, not `9.0`).
- `isReleaseVersion`'s `VERSION` regex is a hand-written parser with the same shape
  (`X.Y.Z` plus an optional dotted alphanumeric pre-release).
- `BINARY`/`ENGINE` regexes are segment parsers with the same accept set
  (`omo-<os>-<arch>[-musl][-baseline][.exe]`,
  `senpi-desktop-engine-(checksums.txt|<os>-<arch>[.exe])`).
- `\bomo-install-qa\b` is a word-boundary token scan; `/PowerShell/i` is a case-insensitive
  substring; `/^(curl|Wget|fetch|HTTPie)\//i` is a case-insensitive head match before `/`.
- `Response::ok()` is `200..300`, matching `Response.ok`.
- `RouteError` carries the two failures upstream lets reject (a database batch error and a
  transport-level `fetch` error); the platform maps them to a 500.

## Deviations (documented, no silent improvement)

1. **`cf.country`.** `requestCountry` reads the Cloudflare `cf` request property. The port
   models it as `Request::cf_country` (host-supplied) and falls back to `"XX"`, exactly as
   `requestCountry` does when the property is absent.
2. **`waitUntil`.** Modelled as a deferred edge-cache population (`CachePopulation`),
   because cache population is the only deferred work the service performs. `scheduled`
   returns the rollup result instead of wrapping it in a `waitUntil`; the native host owns
   where the cron work runs.
3. **Edge-cache matching.** `Cache.match` is keyed on the canonical GET URL plus the request
   headers that participate in matching; the local adapter keys on the URL, exactly as the
   upstream `FakeCache` does, so a `Range` lookup finds a populated non-range entry.
4. **D1 surface.** `db.prepare(sql).bind(...)` is `Statement::new(sql).bind(...)`;
   `db.batch([...])` is `DownloadDatabase::batch` returning one row set per statement
   (empty for a non-`SELECT`), which is what `readDownloadStats` destructures.
5. **R2 object shape and HTTP metadata.** `R2Object`/`R2ObjectBody` become
   `ObjectMeta`/`StoredObject`; `StoredObject` carries `http_metadata: HttpMetadata` (the
   six stored fields) and `write_http_metadata` applies each present field to its header,
   mirroring `R2Bucket::HeadResult::writeHttpMetadata`. `serve_release.rs` calls it first
   and only then sets `Content-Type`/`Content-Disposition`/`Cache-Control`, exactly the
   order of upstream `objectResponse`, so stored metadata survives for the other fields
   and loses for those three. `cacheExpiry` is a `Date` rendered by `toUTCString()`
   upstream; this crate carries no date type, so the host supplies that HTTP-date string.
   Regression: `tests/parity/metadata.rs` (GET, HEAD and the edge-cache boundary).
6. **`Number(value)` coercion.** The rollup parser's `count` column accepts the
   JSON-relevant subset (number, string including the empty string, boolean, null) and
   rejects arrays/objects as `NaN`, matching the upstream coercion for those inputs.
7. **The upstream `rollupQuery(dataset, days = ROLLUP_DAYS)` default parameter.** Only the
   default (7) has a caller, so the port exposes `rollup_query(dataset)`; the window
   literal `ROLLUP_DAYS - 1` is preserved verbatim.
8. **QA driver.** Upstream drives the Worker through `wrangler dev`. The native equivalent
   is `tests/parity/http_driver.rs`: a real client over a local `127.0.0.1:0` HTTP/1.1
   listener that routes into `get_worker::route`. It re-proves the ported route/rollup
   contracts at the real socket boundary and is QA-only, never a shipped entrypoint.
9. **`wrangler.jsonc`.** Remote deployment is unauthorized, so the deploy config is pinned
   by its machine-consumed fields (`tests/parity/wrangler.rs`) rather than exercised.

## Blockers (no false parity)

- **Cloudflare remote bindings are platform-blocked.** R2 `RELEASES`, D1 `DB`, Analytics
  Engine `DOWNLOADS`, the edge `cache` and `waitUntil` have no local equivalent. This
  revision authors the bounded traits and deterministic local adapters only; the
  production remote adapters are NOT authored and remote deployment is unauthorized.
- **Windows-native installer behavior** (`install.ps1`, AVX2/registry architecture
  detection, `SendMessageTimeout`) is platform-gated. A Linux run cannot establish it;
  `install.ps1` ships as pinned bytes.
- **Worker entrypoints stay OPEN - Cloudflare `ExportedHandler` ABI.** `src/index.ts`
  exports `default.fetch(request, env, executionContext)` and
  `default.scheduled(controller, env, executionContext)` via `satisfies
  ExportedHandler<Env>`. The immutable upstream establishes only the TypeScript shape: the
  `Env` interface (`env.ts`) and the ambient script declarations (`text-modules.d.ts`).
  The binding objects (`R2Bucket`, `D1Database`, `AnalyticsEngineDataset`, `Cache`,
  `ExecutionContext.waitUntil`) and the module ABI that invokes `fetch`/`scheduled` are
  supplied by the Cloudflare `workerd` runtime; upstream ships no Rust/FFI contract for
  them, so there is nothing native to port and no remote adapter is invented. Closing this
  needs a native host that (a) implements the workerd `ExportedHandler` module ABI and
  (b) binds R2/D1/Analytics/cache through that runtime - neither exists in this repo.
  `route` and `run_downloads_rollup` are the native seams; the host entry is the
  interfaces release/publish path. This gap is OPEN, not complete.

## API shape notes

- The TS package is async throughout; the Rust port is synchronous (blocking IO and
  `std::process`). Sequencing and observable order are preserved; the async wrapper
  was a Node runtime artifact, not behaviour.
- `IsolationUnavailableError` / `IsolationExistsError` / `IsolationBaselineTooLargeError`
  / `GitCommandError` / `GitCommandTimeoutError` / `IsolationCommitReplayError` /
  `CloneError` are one `IsolationError` enum with `is_unavailable()` and `code()`
  (`"isolation_unavailable"`, `"isolation_exists"`), preserving the fallback predicate
  and the machine-readable codes.
- `IsolationBackend.relocate?` becomes a trait default of `std::fs::rename`, matching
  `relocateSandbox`'s `backend.relocate ? … : rename` branch exactly; `IsolationHandle`
  therefore always exposes `relocate`.
- `bun:ffi` is replaced by native syscalls: macOS `clonefile` (`extern "C"`), Linux
  `ioctl(FICLONE)` (`libc::ioctl`), Windows `CreateFileW`/`SetFilePointerEx`/
  `SetEndOfFile`/`DeviceIoControl`/`CloseHandle`/`GetDiskFreeSpaceW`
  (`extern "system"`, linked `kernel32`). No `.node` sidecar, no FFI shim, no no-op
  fallback. `unsafe_code = "allow"` is the crate-level lint entry for this (see
  `Cargo.toml`).
- `BaseDirIO`/`BackendRuntime`/`OwnerProbe`/`WindowsCloneApi`/`CloneSymbols`/
  `ReflinkIoctl`/`BaselineRunGit` are Rust traits so the tests inject the same fake
  native/CLI boundaries the TS tests inject.
- `IsolationMergeResult` serializes with `#[serde(flatten)]` over `MergeState`, so the
  written `isolation-summary.md` JSON has the same key set as `JSON.stringify(result)`.
- `WorktreeBaseline`/`RepoBaseline`/`NestedBaseline` and `DeltaPatchResult`/`NestedPatch`
  derive `serde::Serialize`/`Deserialize` with `rename_all = "camelCase"`: the consumer
  (`senpi-task/src/isolation/baseline-store.ts`) persists the baseline with
  `JSON.stringify`/`JSON.parse`, so the on-disk `baseline.json` keys must be the TS
  spelling (`repoRoot`, `headCommit`, `untrackedFiles`, `untrackedPatch`, `relativePath`).
- `detachGitDir` returns `DetachOutcome` (`"no-git" | "independent" | "detached"`)
  instead of the TS string union.

## Deviations (documented, no silent improvement)

1. **memory-core seam (required).** The TS `process-identity.ts` imports
   `createProcessStartIdentityReader`, `getProcessStartIdentity` and
   `startIdentitiesConflict` from memory-core, plus `readDarwinProcessStartSeconds` /
   `readWin32ProcessCreationFiletime` from memory-core's `process-start-time`. The
   Rust `maho-memory-core` currently exports only
   `locks::get_process_start_identity` and `locks::get_pid_liveness`. The port reuses
   `get_process_start_identity` and carries a local `start_identities_conflict` (the
   pinned scheme-comparison, 8 lines). REQUIRED from the memory-core owner:
   `pub fn start_identities_conflict(recorded: &str, actual: &str) -> bool` so the
   local copy can be deleted. The darwin/win32 readers are not needed: both writer and
   reader of an owner marker use the same native `get_process_start_identity`, so the
   identity token scheme is internally consistent (it follows native memory-core, not
   the TS `proc-start-epoch:`/`win32-creation-filetime:` spellings).
2. **`ensure.ts` git-consistency probe.** The TS `ensureIsolation` `start`/`stop`
   members are structurally typed; the Rust `IsolationBackend::start` returns
   `Result<Option<StartDetail>>` and `stop`/`relocate` are trait methods. `StartDetail`
   carries the optional `strategy_detail` the APFS backend returns.
3. **`rcopy.ts` embedded-repository copy.** The TS `cp(..., { preserveTimestamps: true,
   filter })` is ported as a `create_new`-guarded recursive copy that also re-applies
   the source mode. This is a superset of `fs.cp`'s default mode handling; recorded
   here rather than silently tightened.
4. **`git/detach-git-dir.test.ts` "ensure retries one inconsistent clone … then refuses
   repeated corruption"** is one TS test with two halves. The Rust port keeps the first
   half in `tests/parity/git_detach.rs`; the second half (persistent corruption is a
   hard failure, not a capability gap) is asserted by
   `tests/parity/ensure.rs::git_snapshot_inconsistency_after_retry_is_a_hard_failure_not_a_fallback_signal`.
   Both halves are covered; only the test-count row is 1:1.
5. **`merge.test.ts` concurrent patch/branch cases.** The TS `Promise` interleaving is
   ported with `std::thread` + `Condvar` gates and asserts the same six-event sequence
   (`first:waiting, first:acquired, second:waiting, first:released, second:acquired,
   second:released`). No timing assertion, no sleep.
6. **`apfs.ts` platform seam.** `ApfsBackend` carries a `platform` field (default
   `platform_name()`) so the loader-classification tests can exercise the darwin branch
   on any host, exactly as the TS tests stub `process.platform`. Behaviour on darwin is
   unchanged.
7. **`fs-integration.test.ts` roundtrip gating (test harness only).** Upstream gates the
   `btrfs`/`reflink`/`rcopy` roundtrips together on `ISOLATION_TEST_BTRFS_ROOT`. `rcopy`
   copies through the ordinary tree walker and needs no special filesystem, so the Rust
   case always runs against a private temporary root (`test_support::fixture()`, removed
   on drop); only `btrfs`/`reflink` stay gated on the btrfs mount. Production behaviour is
   unchanged.
8. **`fs-integration.test.ts` ZFS fixture (test harness only).** The ZFS case requires the
   fixture dataset to be declared disposable with `ISOLATION_TEST_ZFS_DISPOSABLE=1` before
   it runs, so a production dataset can never be snapshotted, cloned or destroyed by
   accident. It restores the upstream clone-mountpoint assertion (`zfs get -H -o value
   mountpoint <dataset>/omo-integration-zfs` == `mergedDir`) that the first port dropped,
   tears down through `cleanup_isolation`, and asserts the backend destroyed exactly the
   clone (`<dataset>/omo-integration-zfs`) and snapshot (`<dataset>@omo-integration-zfs`)
   it created while `<dataset>` itself survives. Upstream's optional
   `ISOLATION_TEST_ZFS_SUDO=1` argv prefix is not ported (the Rust `SystemRuntime` runs
   `zfs` directly; a non-delegated dataset must be delegated to the test user instead) -
   recorded, not silently dropped.

## Behavioural deviations

- `runJsonRpcStdioServer` becomes `run_json_rpc_stdio_server(input, output, config)`, which returns `Result<ServerOutcome, ServerError<E>>`. TS resolves with `void` whatever the stop reason; the Rust `ServerOutcome` makes the reason observable (`InputClosed`, `IdleTimeout`, `ParentExit`, `TerminalOutputError`).
- `handlerOptions` is dropped because a Rust handler closure captures its own state. The handler is synchronous (`FnMut(&Value) -> Result<Option<JsonRpcResponse>, E>`).
- Input is read on a worker thread, and the dispatch loop re-checks stop conditions every 25 ms. The TS event loop reacts to the watchdog immediately; the port reacts within one slice.
- Terminal output errors: TS matches `EPIPE`, `ERR_STREAM_DESTROYED` and `ERR_STREAM_WRITE_AFTER_END`. Only `EPIPE` has a Rust `io::Error` equivalent (`ErrorKind::BrokenPipe`).
- Outside unix, `is_process_alive` always reports alive (there is no portable signal-0 probe), so the watchdog never fires there.

## Sibling gaps

None. The crate depends only on `serde` and `serde_json`. The unix liveness probe declares `kill(2)` directly instead of adding `libc`, so the workspace lockfile does not change.

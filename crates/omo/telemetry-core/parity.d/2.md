## Intentional deviations
- `runtime` / `runtime_version`: TS emits `"bun"` / Bun's version; Rust emits `TELEMETRY_RUNTIME` (`"rust"`) and the crate version. The field names are unchanged.
- `locale`, `timezone`, `shell`, `terminal`: TS always sets the key (JSON drops `undefined`). Rust omits the key when the value is unavailable, so the serialized wire output is the same.
- JS `undefined` property values map to `Value::Null`. Both are rejected with `telemetry_event_property_rejected`.
- `posthog-node` has no Rust port, so `PostHogTelemetryTransport` is a minimal `/batch/` client over reqwest that honours `flushAt`/`flushInterval`, `$geoip_disable`, and explicit flush/shutdown. The `TelemetryTransport` trait keeps it swappable. `telemetry_posthog_import_failed` stays in the enum but is never emitted, because there is no dynamic import.
- `TelemetryClient::flush` and `record_daily_active` return `Result`, matching the TS promise rejection on flush failure.
- `SystemTelemetryOsProvider` reports `node:os` vocabulary (`darwin`, `arm64`, `Darwin`). It uses `uname`/`sysctl`/`/proc` and needs no unsafe FFI.

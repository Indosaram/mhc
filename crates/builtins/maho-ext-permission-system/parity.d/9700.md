`auto_credentials::is_credential_path` is the auto-preset name check from `auto-credentials.ts`. It is distinct from `external_dir::is_credential_path` (external_dir.rs:84), which guards mhc's own `auth.json` for the SD-1 `credential_file` permission.

The modules are not yet declared in src/lib.rs, and their dependencies are not yet in Cargo.toml. Both files are outside this lane's write scope, so the exact lines are filed as registry requests. Until those lines land, the modules and their tests are not compiled.

`preset-registry.ts` keys a WeakMap by the SessionManager object. The Rust port keys by session id and compares readers with `Arc::ptr_eq`, which gives the same "retiring an older load never removes a newer one" rule.

dispatch*.ts stays open: it needs the per-session dispatch authorizer and approval fence inside AgentSession/MCP dispatch (maho-core, senpi-mcp). It also needs `ToolInfo.parameters` object identity, which has no Rust equivalent.
read-permission.ts stays open: it needs `getBundledResourceRoots()`, which mhc does not have, and its registration lives in src/parsers.rs.

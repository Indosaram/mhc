Notes:
- The restore digest now names every monitor and background session (`RestoreDigest.results` / `background_sessions`), and replaces the old count-only `<system-reminder>`. It is delivered on SessionStart, ModelSelect and user Input once a model is bound; with `terminal.notify: off` only the user sees it (`ui.notify`).
- A held or unacquirable lease records a deferred digest, sets the `terminal-restore` status, and starts a lease keeper. Its takeover adopts the lease (`TerminalStateLifecycle::adopt_lease`) and runs the same restore. Shutdown stops the keeper, awaits a tick that is still in flight, then awaits the restore in flight (upstream `restoreInFlight`: a takeover's `own` and the detached grace-window `decide`) before `observe_monitor_state`, `record_shutdown` and `release`.
- orphan_reaper is not wired: the native manifest records no child process identity (pid, pgid, start time, boot time, argv) for a command watch, so there is nothing to confirm before respawn. Wiring it needs a manifest-model field plus `durable_command` support, which is the lease v2 / process-identity follow-up.
- Downtime is measured from the manifest's `updatedAt` to now (upper bound), as upstream does.
- `TakeoverContext` carries upstream `whenRestoreDecided` (a watch channel set after `own`) and `restoreSessionTestHooks.keeperIntervalMs` (`keeper_interval_ms`, `None` in production), so the takeover tests await the decision instead of sleeping.
- restore-session (c) pid reuse: `TerminalStateLifecycle::acquire` uses `acquire_terminal_lease_with` with the real `read_process_start_ms` probe, so a lease whose pid now belongs to a later-started process is reclaimed at session start (`persistence_tests::a_lease_held_by_a_reused_pid_is_reclaimed_at_session_start`). The v1 lease record is enough; no token is needed.
- restore-session (a3)/(d): a respawned command watch counts as restored only if it is still running when `RESTORE_GRACE_MS` (2 s) closes. An exit 0 inside it is `completed`, a non-zero exit is `lost` with `exited <code> in <ms>ms: <first output line>`. Neither is kept, and a readable manifest is rewritten at once (`persistRestored`). The grace window runs on a detached task, as upstream does, so session_start never waits on it; the decided digest is flushed when it settles. Tests: `a_completed_watch_is_gone_from_the_manifest_and_never_rerun` and `a_lost_script_carries_its_exit_reason_and_lost_and_expired_state_dirs_go`.
- restore-session (e) two-process race: `terminal_state::tests::two_racing_acquirers_leave_exactly_one_owner` releases two threads through a barrier into `acquire`; exactly one owns the lease. The race is between threads, not processes. The exclusive publish is the same file-system primitive either way.
- Still OPEN: restore-session (a)/(a2) crash respawn with orphan kill. The native manifest records no child process identity (pid, pgid, start time, boot time, argv) for a command watch, and `orphan_reaper` is not wired into the restore, so there is no orphan to confirm and kill. The lease v2 token is not the blocker.
- restore-session (g): SessionStart/SessionShutdown resolve the state dir through `monitor_state_dir::terminal_state_dir`, which skips print and json like upstream `terminalStateDir`, so a one-shot start takes no lease and records no manifest (`terminal_lifecycle::a_print_or_json_start_takes_no_lease_and_records_no_manifest`).
- restore-session (g2): an unreadable manifest is left byte-for-byte and the decided digest is `corrupt` (`persistence_tests::an_unreadable_manifest_is_left_exactly_as_it_was`).
- restore-session (h)/(h2): lease v2 tokens (`manifest_lease.rs`) make a same-pid lease re-enterable once its generation retired its token. An in-process resume rotates the token and owns the lease (`terminal_lifecycle::an_in_process_resume_rotates_the_token_and_is_never_held_by`), and a stale same-pid record left by a cut-short shutdown is re-entered (`terminal_lifecycle::a_same_pid_lease_left_by_a_cut_short_shutdown_is_re_entered`). These assert the lease and token, not the restored digest entry.
- restore-session (i): a watch created while waiting on a foreign holder is queued (`handMonitorSpec`), drained into the takeover's writer and on disk with the restored watch (`persistence_tests::a_watch_created_while_waiting_is_on_disk_after_the_takeover`). The spec is handed to the binding directly, not through the monitor tool.
- Shutdown during the grace window: the shutdown ends the generation and cuts the window short (native divergence: upstream waits the window out), so a still-running watch counts as restored, stays in the manifest with its state dir, and no digest is set or sent after shutdown (`persistence_tests::shutdown_inside_the_grace_window_keeps_the_watch_and_sends_no_digest`).
- Stale generation: a restore overtaken by a newer generation returns right after its grace window with no `forget_restored`, `persist_restored`, sweep, flush or decided signal (upstream `if (generation !== state.generation) return`), asserted by `persistence_tests::own_from_a_stale_generation_sets_no_digest`.

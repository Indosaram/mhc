Notes:
- `monitor-types.ts` `allocateMonitorId` is src/monitor_registry.rs:92.
- `terminal-manifest-parse.ts` (`InvalidTerminalManifestError`, `parseTerminalManifest`) is
  src/restore.rs:6 and src/restore.rs:141.
- `process-start-probe.ts` `readProcessStartMs` is `read_process_start_time` +
  `process_start_time_ms` in maho-tool-child group_ownership.rs:288/337 (also
  crates/maho-cli/src/cli/schedule_watch.rs:107).
- `lease-file.ts`: ported into src/manifest_lease.rs (`publish_exclusive` via hard link,
  `publish_replace`, `reclaim_lock_state`, `break_stale_lock`, `reclaim_inspected`). An acquire
  removes a dead, reused or unparseable lease only under `<lease>.lock` and only while the file
  still holds the inspected bytes, so two concurrent reclaims cannot both acquire (handshake test
  `concurrent_reclaim_of_one_dead_record_acquires_exactly_once`, bounded by `recv_timeout`). `errorCode`, `unlinkIfPresent`
  and `readLeaseText` are io::ErrorKind matches and private helpers. Divergence: the lease record
  stays v1 `{pid, startedAtMs}` (no token/boot fields), so there is no `self` re-entry class.
- `process-identity.ts`: `ownProcessStartedAtMs` derives `process.uptime()` from
  `/proc/self/stat` on Linux; other platforms use module first use (no `workerData` host start).
- `lease-keeper.ts`, `terminal-state-gc.ts`: adapted to the native v1 `{pid, startedAtMs}` lease
  record, where `startedAtMs` is the acquisition instant. A reused pid follows upstream's one-sided
  v1 `classifyLease` rule: the process wearing the pid started more than 3 s after the lease was
  taken. The keeper's tick polls file + pid liveness only (as upstream); the start check runs in
  `acquire_terminal_lease_with` when it acquires. `read_process_start_ms` is Linux-only
  (`/proc/<pid>/stat`); elsewhere the start is unknown and a live pid stays the holder.
  `on_takeover`, `on_tick` and `on_error` run with the keeper mutex released; the post-acquire
  state check and the Owner transition share one lock. The GC removes a stale lease only through
  `reclaim_inspected` and breaks a `.lock` only when `reclaim_lock_state` calls it stale (upstream
  terminal-state-gc.ts), so a lease replaced between inspection and removal survives and a lease
  whose reclaim lock a live process holds is left alone. Like upstream's
  `readProcessStartMs ?? defaultReadProcessStartMs`, a sweep without a `read_process_start_ms`
  option probes through `manifest_lease::read_process_start_ms`, both for reused-pid leases and
  for reclaim locks. A tick restores `on_tick` only if no `set_on_tick` ran during it (generation
  counter), so clearing it mid-tick sticks.
  Divergence: src/terminal_state.rs (not owned by this lane) still acquires through the
  liveness-only `acquire_terminal_lease`, so the reused-pid start check is active only in the
  keeper path (`acquire_terminal_lease_with`).
- `rpc-monitor-targets.ts`: `endpointSockets` (enumerating the host's rpc endpoint sockets) is
  not ported; it needs maho-rpc host endpoints, which are not a terminal dependency.
- `tools/monitor-schema.ts`: 7 of 8 exports are ported in src/tools/monitor_schema.rs.
  `monitorSchema` is NOT at parity: src/tools/monitor.rs `monitor_schema` lacks `type`,
  `target`, `events`, `exclude` and `human_input` (and adds `wakes_per_hour`). The schema half is
  requeued to senpi-builtins-a, which owns tools/monitor.rs.
- `rpc-monitor-render.ts`: the per-batch label set clears at `end_batch` (upstream microtask). The
  unknown-kind JSON filters `type`/`sessionId` out instead of `Map::remove` (a `swap_remove` under
  `preserve_order`), keeping upstream key order.
- `restore-digest.ts`: per-monitor results come as `RestoreDigestInput`; the native
  `restore::RestoreDigest` counters are unchanged. The notice renderer registration is not ported.
- `orphan-reaper.ts`: Windows evidence (CIM) is not read; win32 never kills on confirmation.
- `monitor-permission.ts`: the non-enumerable symbol slot is the private `approved_parent`
  field (src/monitor_permission.rs:2), not reachable from model JSON; `monitorParent` is
  src/monitor_permission.rs:8.
- `monitor-file-digest.ts`: sampled hash and pre-read abort guard (src/monitor_file_digest.rs:8).
  Binding the signal to file registration belongs to `file-monitor-registration.ts`, not this file.

# sync-5152 compaction-rest (senpi v2026.10.27-2)

UTF-16 rows: every ported slice cuts at the same UTF-16 unit index as senpi. A cut through a
surrogate pair leaves a lone surrogate in JS; a Rust string cannot hold one, so that half decodes
to U+FFFD, which is also one UTF-16 unit. Lengths, `text.length`-based token estimates, the
`kept N of ~M` counts and truncation-note counts therefore equal upstream exactly; only that one
code unit's value differs (it is replaced on the wire by `sanitizeSurrogates` upstream anyway).
The earlier six-character `\uXXXX` escape changed every downstream length and is removed.

- tool-admission.ts / orchestration.ts: excerpt budget uses senpi's double ratio
  `floor(budget * (len / total))`; `admitContextToolResult` is ported.
- tool-truncation.ts: head 800 / tail 400 units without pair rounding.
- restoration-tracker.ts / resume-slice.ts: JS `trimEnd`/`trim` (ECMAScript whitespace) and the
  ASCII hyphen header.
- overflow-retry.ts: `TRUNCATION_NOTE` accepts only `\d+`; counts print as JS numbers.
- todo-bridge.ts: `readTodoPayload` keeps the ask on legacy `todos` payloads; any numeric
  `capturedAt` is an ask.
- openai-remote-responses-v2.ts / openai-remote.ts: both stream routes await the extension
  `transformPayload` inside the provider's async payload hook and re-validate the result.

- speculative-summary.ts / speculative.ts: the summary stream forwards the session cwd as
  `ProviderRequestOptions.cwd` (`{...options, cwd: context.cwd}`).
- context-pipeline.ts / openai-remote.ts: `markOpenAiRemoteReplayBoundary` seals the checkpoint
  markers through the Responses converter (maho-ai `seal_context_provenance`, carried as an
  index-aligned side channel because a typed message cannot hold senpi's non-enumerable field),
  and the `before_provider_request` hook runs `rewriteOpenAiPayloadWithRemoteCompaction` with the
  identity, origin and unproven-boundary fallbacks. The sealed boundary travels beside the request
  (the latest live context event's) and is proven by item equality with the sealed items, which
  fails exactly where senpi's integrity fingerprint would. Because items are compared instead of
  message fingerprints, the sealed baseline is converted with the request's tool declarations
  (active tools with their freeform and grammar formats, plus the matching grammar input
  properties), so a kept `apply_patch` call seals as the same `custom_tool_call` the request sends.
  As upstream rejects extra boundary items, a sealed item with its own `id` or `call_id` that
  appears again after the replaced prefix leaves the boundary unproven (senpi tells copies apart by
  object identity; equal user turns without an item id are distinct turns, not copies).
  Every live context event clears the stored boundary before it runs, so a failed event cannot
  leave a stale one (senpi's boundary lives on the request's own items and has no such state).
  The live header builder reads the kernel release once per process (`OnceLock`), so the per-request
  replay hook spawns no `uname`/`ver` process off Linux.
  The replay hook checks for a remote checkpoint on the branch before it asks the registry for
  auth; with none the rewrite would return untouched anyway (an optimisation, not senpi order).

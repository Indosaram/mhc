## Actual repairs (confirmed divergences)

**Step-up — ported.** `src/auth/step_up.rs` is a line-for-line port of `mcp-oauth/step-up.ts`
(`parseWwwAuthenticate` → `parse_www_authenticate`, `mergeScopes` → `merge_scopes`,
`isStepUpRequired` → `is_step_up_required`, `extractParam` → `extract_param`: quoted
`${name}="([^"]*)"` first, then bare `${name}=([^\s,]+)`, each taking the leftmost match; the
`bearer` search is case-insensitive and the scope is the whitespace split of the quoted/bare
`scope`). `src/transport_sdk.rs::http_send` now reads the `WWW-Authenticate` response header on a
non-2xx response and routes it through `retry_after_challenge`, which mirrors the pinned
`manager.ts::withOperationRetry` handling:

- `403` + a parseable challenge → `oauth-handler.ts::handleStepUpIfNeeded`: `mergeScopes` into the
  provider's requested scopes (`McpOAuthProvider::escalate_scopes`), then the bound
  `McpAuthStepUp::login` (the real interactive `provider.login()` through
  `commands_auth::run_interactive_login`) and `McpAuthStepUp::reconnect` (the real
  `ServerConnection::renew`), and one retry **on the renewed client**; a bare transport with no
  handler keeps the escalation + same-client retry;
- `401`/`403` → `oauth-handler.ts::handlePostRequestAuthError` single-flight refresh
  (`McpRefreshManager::force_refresh`, which bypasses `refresh_locked`'s staleness short-circuit
  exactly as the pinned `provider.refresh(refreshToken)` does) then one retry;
- each is attempted at most once per request (the pinned `refreshAttempted` set + `maxRetries`).

The failing error now carries the challenge: `cause = {status, wwwAuthenticate, requiredScopes}`.

**HTTPS — repaired.** `oauth.rs::parse_https_url` is the pinned `discovery.ts::parseHttpsUrl`
(`<label> must use https`), applied to the resource URL (`Resource server URL`), the issuer
(`Authorization server URL`) and, in `parse_metadata_fields`, `authorization_endpoint`,
`token_endpoint` and `registration_endpoint`, each stored in its `URL.toString()` normal form.
Production defaults to `McpOAuthProvider::require_https = true`; the deterministic loopback HTTP
fixtures opt out explicitly (`require_https = false`) — a test-only seam, never a production
default (pinned by `tests/oauth_transport_hardening.rs::production_default_requires_https`).

**URL-query redaction — repaired.** `log.rs::redact_url` ports `http-client.ts::redactUrl` (query
params whose key contains `key`, `token` or `secret` → `***REDACTED***`), and
`log.rs::redact_urls_in_text` ports the `redactCleanupErrorMessage` URL pass. The HTTP transport
applies it to the `request.send()`, `response.chunk()` and `response.json()` error text in
`transport_sdk.rs`, so a `reqwest` error message carrying `…?token=…` no longer leaks the value.

**Discovery / resource indicator / DCR** were repaired in the earlier pass of this unit (native had
been ported from the wrong source): origin-form PRM URL, required `authorization_servers`, surfaced
non-404 PRM status, the origin retry for `oauth-authorization-server{path}`, required
`authorization_endpoint`/`token_endpoint`, the RFC 8707 `resource` normalization, and the pinned
`ClientRegistrationRequest` shape (no `scope`, `client_name = oh-my-openagent`).

## Interactive step-up — repaired (pinned `provider.ts::login` + `manager.ts::forceReconnect`)

The pinned `handleStepUpIfNeeded` completes a step-up by calling `provider.login()` (the interactive
browser authorization) and `manager.ts::withOperationRetry` then calls `forceReconnect`. That
re-login and reconnect are now implemented **inside the owned crate** (the earlier pass's
"unsupported native API" claim is withdrawn — the seam is internal, not a platform blocker):

- `transport_sdk.rs::McpAuthStepUp` is the service-owned seam the transport invokes
  (`login(required_scopes)` then `reconnect() -> Arc<McpClient>`); `McpClient::set_step_up` binds it.
- `auth/step_up_login.rs::McpInteractiveStepUp` is the production handler. `login` rebuilds the
  provider from the config with `mergeScopes`d scopes (the pinned `authProviders.delete(url)` +
  `getOrCreateAuthProvider(...)`, so no `&mut` handle into the `Arc<McpOAuthProvider>` is needed) and
  runs `commands_auth::run_interactive_login` — the same `build_provider` + `run_loopback_auth` path
  `service.rs::McpService::auth` drives. `reconnect` calls `ServerConnection::renew` and returns the
  renewed client, so the retried operation runs on the fresh connection (pinned `forceReconnect`).
- `oauth.rs::begin_authorization_forced` / `commands_auth::run_loopback_auth_forced` are the pinned
  unconditional `provider.login()`: the `/mcp auth` entry keeps the idempotent stored-token
  short-circuit, the step-up re-login does not.
- `commands_auth::open_browser` ports `oauth-authorization-flow.ts::openBrowser` (`open` /
  `explorer` / `xdg-open`, detached). The handler surfaces the URL through it and additionally
  notifies the bound `ExtensionUi` when one exists (the port's existing surfacing convention for the
  same flow); `set_browser` overrides the launcher so the deterministic fixtures drive the loopback
  callback instead of spawning a browser.
- `service_connection.rs` binds the handler to every created `ServerConnection`; `connection.rs`
  propagates it into the transport; `service.rs::McpService::auth` now shares
  `run_interactive_login` with the step-up path.

The final error still carries `requiredScopes`, and a failed re-login falls through to the pinned
post-request refresh (`ignoreOAuthFallbackError`).

## Recorded deviations (need an N/A reason or an owner decision)

- **Cache — repaired (pinned `discovery.ts`).** `oauth.rs` holds the process-local
  `DISCOVERY_CACHE` + `PENDING_DISCOVERY` in-flight coalescing keyed by
  `new URL(resource).toString()`, with `reset_discovery_cache()` (pinned `resetDiscoveryCache`), and
  it is never persisted: `McpStoredAuth` no longer carries `discoveryState`, and
  `token_store::migrate_stored_auth` drops a legacy `discoveryState` on read/write while preserving
  every other field (including forward-compatible `extra` keys). Every pinned consumer reads it:
  `begin_authorization`, `finish_authorization`, `client_credentials_grant` and
  `oauth_refresh::refresh_locked` (now the cached `discover`). `CredentialScope::Discovery` maps to
  `reset_discovery_cache()`.
- **Env cleaner — repaired (pinned `env-cleaner.ts`).** `env_cleaner.rs` ports
  `createCleanMcpEnvironment` (ambient minus `EXCLUDED_ENV_PATTERNS`, declared env overlaid
  unfiltered). The production consumer `transport.rs::create_mcp_transport_spec` filters the host
  session environment (this port's `process.env`) with the pinned blacklist before overlaying
  `config.env`; `diagnose.rs` uses the same cleaner for its rerun. `materialize_stdio` keeps its
  `env_clear()` + system-key re-add (`HOME`/`PATH`/…) as the native fallback for a child that must
  find its interpreter; in production this is behaviourally identical because the session
  environment already carries those keys.
- **Logger marker.** `redactSensitiveData`'s literal `[REDACTED]` is not the shipped
  `log.rs` `<redacted:fp>` contract; the shipped logger contract is kept (covered by
  `tests/auth.rs::saved_oauth_tokens_log_only_the_fingerprint`) and only the missing URL-query
  redactor was added.

## Registered HTTPS command acceptance (SC-U2)

`tests/registered_command_auth.rs` adds one role-branching test through the
production ExtensionRunner and registered mcp command. The child serves real
TLS discovery, DCR, authorization, token exchange and MCP initialization;
the parent supplies an isolated CA through subprocess SSL_CERT_FILE without
disabling chain or hostname verification. Parsed authorization and DCR fields,
stored credentials, bearer reconnect, replay rejection without another exchange,
logout deletion and notification secret absence are asserted.

The subprocess lifetime, session/registry teardown and server join are bounded;
failure output is redacted. A successful scenario requires teardown success and
listener release. No sleeps or polling are used. Invocation and cleanup design
are recorded in the SC-U2 scenario receipt. This test is authored but UNRUN;
neither this row nor the receipt establishes final product acceptance.

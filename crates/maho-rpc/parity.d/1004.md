N/A reasons for the counts above:

- `test/rpc-host-lifecycle.test.ts` (28) covers the whole supervisor: the public socket and its
  secret, the observer link, busy-session tracking, supersession and the handoff grace. Those
  behaviours belong to the lane-36 host rows (`host_lifecycle.rs`, `observer_link.rs`,
  `host_supersession.rs`, `host_successor.rs`) and are audited there. This fragment adds the
  lifetime binding the upstream file defines at 513-544 and the ownership token; the Rust cases
  here pin exactly those, and the end-to-end supervision is driven by the authored QA driver
  (`tools/latest-omo-host-qa.mjs`, scenarios `lifecycle`/`idle-exit`/`watchdog`).
- `test/rpc-socket-host.test.ts` (18) covers the accept loop, per-connection routing, retained
  sessions and the drain path. The Rust cases here pin the host's own lifetime (protocol answer,
  empty-exit, endpoint removal); the routing/retention rows are the lane-36 session rows.
- The fd binding carries the inherited descriptor's real number instead of a hardcoded `3`
  (senpi `CHILD_WATCH_FD`). Rust's `Command` exposes only the three standard stdio slots and
  `pre_exec` is unavailable under this crate's `unsafe_code = "forbid"`, so the read end's
  close-on-exec flag is cleared and `HOST_WATCH_FD_ENV` names the descriptor the child inherits.
  The EOF semantics the watchdog depends on are unchanged. The read itself is a plain OS thread
  blocked in `read(2)`, not a tokio blocking-pool job: a pooled read parked in the pipe is not
  cancelled by `abort` and tokio joins every blocking worker on runtime drop, which is exactly the
  exit hang senpi documents for a thread-pool read.
- Windows: the fd binding is Unix-gated (`bind_child_watch_pipe`); on win32 the child gets only the
  ppid fallback and the cleanup paths. The Win32 named-pipe close path is not ported and its QA is
  BLOCKED, not waived.
- `rpc-client.ts` upstream has no `abortSession` method; `abort_session` is the addressed form of the
  existing `abort` the `closeHostSession` writer needs (upstream `runners/rpc-host/close.ts` sends a
  bare `{type:"abort"}` on a client already attached to the target session). It has no upstream unit
  test; the end-to-end close path is driven by `tools/latest-omo-host-qa.mjs`.

## 3. Proposed env var for the parent session

- **Needed: yes.** The child must write `spawnedBy.parentSessionId`. It cannot derive it.
  `MHC_TASK_ROOT_SESSION` names the root, which differs from the parent at depth >= 2 (D1 test 3
  and team D1 test 2). The state directory name is a sanitised session id (`record.rs`
  `default_state_root`), so it cannot be reversed. A command-line flag would also work but would
  change the `-p` interface for every caller. One variable next to the existing three is the
  smallest change.
- **Name:** I renamed it to `MAHO_TASK_PARENT_SESSION` in task.md, as the project keeps the
  `MAHO_` prefix for new env vars. A grep over the repo finds no existing `MAHO_TASK*` name, so there is no
  collision; the `MAHO_*` names in `crates/` (`MAHO_GATEWAY_DIR`, `MAHO_SKILLS_ROOT`,
  `MAHO_TEAM_*`, ...) are unrelated. The existing `MHC_TASK_DEPTH`, `MHC_TASK_ID` and
  `MHC_TASK_ROOT_SESSION` are shipped interface names (maho-task, maho-workpool, maho-telemetry)
  and stay. Mixing prefixes is accepted to avoid renaming shipped variables. team.md and
  workflow-dag.md do not mention the new name.

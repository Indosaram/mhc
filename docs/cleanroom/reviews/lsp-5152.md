## Behaviour check

- D1 matches upstream: only `typescript` carries the defaults. `deno` and the other built-ins
  carry none.
- D2 matches upstream for user entries: no command means built-in defaults shallow-merged with
  the entry, entry wins. An own command means only the entry's options. The spec deliberately
  differs for project entries. Upstream ignores a project entry's `command` for built-in ids,
  but mhc's `merged_servers` accepts project commands, as its existing test
  `project_overrides_user_and_builtin_and_disables` shows. The spec follows mhc's design, which
  is correct for a delta on an MIT port.
- The "Note for maho-lsp" about entries without `command`/`extensions` is accurate. Today
  `merged_servers` skips any entry that lacks either field (config.rs). Upstream fills the
  missing fields from the built-in entry.
- Tests 1-8 agree with the D1/D2 text. Test 4 (shallow merge) matches upstream object-spread
  semantics. Test 7 matches upstream: an unknown id without a command produces no server.

  server command (`host-js-runtime.ts`). It is not part of rows 15/16 and is not specified

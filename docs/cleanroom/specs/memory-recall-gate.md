# Recall nudge gate — clean-room spec

Behaviour reference: `crates/omo/memory-core/src/recall/gate.rs`. Implemented in
`crates/maho-memory/src/recall_gate.rs`.

A nudge is one sentence about a stored note, generated by a sidecar model and inserted into a live conversation.
The gate decides which generated nudges may be inserted.

## Why a gate exists at all

The sidecar's output is untrusted text that arrives with the weight of stored memory behind it. A hint reading
"you should always run the smoke suite first" would be an instruction nobody approved, presented as a remembered
fact. The rules below keep a nudge a **fact about a note**.

## Hint shape

Checked in this order, so a hint is reported under its first failure:

| Reason | Rule |
|---|---|
| `Empty` | no characters |
| `TooLong` | more than 200 **characters** (not bytes) |
| `Multiline` | contains `\r` or `\n` |
| `DecisionCommentary` | talks about whether a memory is relevant |
| `AddressesAgent` | second person, imperative opening, or Korean request/prohibition |

Characters, not bytes: a 200-character Korean hint is admissible, and counting bytes would silently allow only a
third as many.

### Addressing the agent

Four independent tests, any of which rejects:

- **Second person**: `you`, `your`, `yours`, `yourself` as whole words.
- **Imperative opening**: one of 19 verbs (`never`, `always`, `ensure`, `run`, `use`, `read`, ...) after leading
  whitespace and quotes. The verb must end at a word boundary, so `Runners cache the toolchain.` and `Useful notes
  stay local.` are admitted — a noun that happens to start with a verb is not a command.
- **Korean request ending**: `세요`, `십시오`, `십시요`, `하라`, `해라`, `합니다`, plus the `…지 마라` form.
- **Korean prohibition**: `하지 마` with optional whitespace before the final syllable.

### Decision commentary

Statements that a memory is or is not relevant are not facts: `No relevant memory found.`, `The memory is
unrelated to this task.`, `Memory does not cover this.`, `The memories cover the deploy path, but not the
rollback.`, `Nothing here clears the bar.`

A genuine fact that happens to mention memory — `The memory directory holds each session separately.` — is
admitted. The rule matches specific relevance statements, not the word "memory".

## Two contracts, deliberately different

`describe_invalid_hint` is the **admission** contract: shape plus addressing.

`is_valid_hint` is the **replay** contract: shape only. Replay re-checks hints written by an older build, which
were legitimate when written; applying today's addressing rule retroactively would silently delete history.

## Parent-side validation

`validate_nudges` accepts, in order, at most `max_items` nudges, each of which must:

1. be a path the parent **offered** (anything else was fabricated by the sidecar),
2. not already be **surfaced** in this session,
3. have a valid hint,
4. be a **first** occurrence of that path.

A rejected nudge is dropped **silently**. The sidecar is untrusted, so rejection is routine, and reporting it
would let the sidecar put text in front of the user by getting itself rejected.

A rejected nudge does not consume the cap: the budget counts accepted nudges, so one bad hint cannot starve the
rest of the batch. Order is preserved — the sidecar ranked them.

## Not ported: the pending-nudge file layer

The reference module also persists pending nudges to disk: `RecallNudge::new`, `PendingNudgesFile`,
`PendingNudges::{new,write,take,delete}`, `parse_pending_file`, `temporary_path`, `remove_quietly`, plus
`PENDING_NUDGES_VERSION` and `PENDING_TTL_MS`. None of it is reproduced here.

That layer is not part of the gate's decision. It is the transport between the process that generates a nudge and
the process that inserts it, and in this crate there is no such split: a caller holds nudges in memory and passes
them to `validate_nudges`. Porting the file format would add a second, unexercised writer with no reader — the
kind of module that looks complete, passes its own tests, and is never called.

Its dependencies confirm the same thing. The reference file layer reads through the SUL git repository type and a
shared `support::time` module; the MIT crate has neither, so a port would have to recreate them first. Writing
file-handle plumbing ahead of the code that needs it is the wrong order.

Revisit only when something in this crate actually has to survive a process boundary between generating a nudge
and admitting it. At that point the format should be designed against the real handoff rather than inherited.

## Not ported: the corpus cache provider

The reference also holds `recall/provider.rs`: a cached corpus of recall documents keyed off a git repository,
with figures for memory accounting. It is a caching strategy over a repository abstraction this crate does not
have. `recall_strategy` here already operates on an explicitly supplied document slice
(`choose_recall_strategy(documents, queries)`), which is what makes it testable without a repository or a clock.

## Verification

`crates/maho-memory/src/recall_gate.rs` covers every hint-shape reason, both addressing contracts, the
offered/surfaced/first-occurrence rules of `validate_nudges`, and the cap accounting. The persistence layer has no
tests here because it has no implementation here; that is the decision recorded above, not an oversight.

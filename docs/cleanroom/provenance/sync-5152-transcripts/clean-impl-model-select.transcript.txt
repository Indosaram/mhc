**What changed**
- **Launch-gated model (D1):** the built-in profiles now drop `claude-fable-5-5` (also matched with `.` instead of `-` or a `provider/` prefix) while the release flag `FABLE55_RELEASED` is off. That flag already exists in `maho-ext-recommended-models`, and the spec only asks to read it, so that crate is unchanged. With the flag on, the rung is kept only at `xhigh` or `max`. Otherwise it goes into a list of dropped rungs and one warning naming the level is logged.
- **`daily-heavy` chain (D1):** the gated model at xhigh, then the current same-family model from the recommended-models data at xhigh, then `claude-opus-5-5` at high. Profiles you define yourself are never filtered.
- **Profile outcomes (D2):** they are now a session entry plus a log line plus at most one notification. The code that sent a custom message to the model is gone. Notification levels follow the spec: a clean apply gets none; auth failures or a configured profile get a warning; the default order with no auth failures gets info; a model the registry dropped gets a warning. Hosts without a UI skip only the notification. If the entry can't be appended, a warning is logged and the notification still goes out.
- **Notice text (D3):** when no model is available, the next step depends on the mode. In rpc it points to the provider settings or picking a model in the client; in other modes it says `/login` or `--model`. The "registry no longer lists it" notice names the profile and the `provider/model`, says the current model is kept, and asks you to pick another model (in settings for rpc, `/model` or `--model` otherwise).
- **OAuth refresh in the probe (D4):** a refresh failure is now either refused or transient, and the check also looks inside wrapped errors. A transient failure keeps the provider, and its warning line carries only provider, model, fingerprint and transport class. If the model-scope check fails for the same transient reason, the candidate is still kept, with no scope result. A refused refresh, or a plain `oauth` code with no split info, still excludes the provider with reason `refresh`.

**Spec ambiguities and what I chose**
1. **Where the D6 re-check reads the configuration:** a new `TelemetryExtension::config_source` hook. By default it reloads `maho_config::load_native(cwd, env)` with the environment captured when the extension registered. If a config file has Read/Parse errors, it keeps the previous values (matching config.md §14). The "no view available" case is an `Err` from the hook, and that fails closed. The tests use a JSON file standing in for the project config, not a real project config.
2. **When the discard diagnostic fires:** once per session, shared by the "turned off" and "unreadable" cases. The count is the number of payloads for the run (up to 3 signals). Wording: `telemetry export skipped because <reason>; discarded N payload(s)`.
3. **Which switches count as turned off:** only an explicit `false` for `telemetry.enabled` or `telemetry.otlpExportEnabled`. A missing key means unchanged.
4. **D2 host-name test:** nothing in the crate reads a host name, so the test sets `HOSTNAME`, `HOST` and `COMPUTERNAME` in the resolve environment and checks the raw payloads.
5. **Cross-process instance-id test:** it re-runs the test binary on the same test with an env flag and reads `instance-id=` from the child's stdout.
6. **D5 Linux x86_64 test:** gated with `#[cfg]` to that target. The mapping test covers every platform on every build.
7. **New injection points:** `TelemetryExtension` has two new fields (`config_source`, `report`), and `Shared::new` / `on_record` / `finish_run` / `flush` are now `pub(crate)` so the tests can call them. `maho-cli` only uses `TelemetryExtension::new` plus a field assignment, so it should still compile, but that is unchecked.

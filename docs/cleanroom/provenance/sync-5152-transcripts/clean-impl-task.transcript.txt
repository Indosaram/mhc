**Spec ambiguities and my choices**
- **D1:** this tree cannot complete D1 alone. The session header has to be written by `maho-core`/`maho-cli`, which were out of scope. The CLI must call `maho_task::current_spawned_by()` when it creates a **new** session and put the result in `spawned_by`.
- **D2:** the exact phrase lists are mine, written as categories from the spec; for example, "401" only counts as a standalone number. "Names a model" is a case-insensitive substring check for "model" or the failed model id.
- **D4:** the parent model is now the last candidate of every category or agent choice, not only on reroute. An explicit model gets no fallback plan. Steers written to a refused attempt are dropped from the inbox before the retry.
- **D7:**
  - "Answered" means any assistant message after the delivery whose `stopReason` is not `error` or `aborted`.
  - An admitted but unanswered steer starts a follow-up with a fixed prompt (`ACT_ON_RECEIVED`).
  - An uncertain steer becomes a hook note, so it shows in the envelope.
  - The transcript file is looked up up to two directory levels deep.
- **D8:**
  - On Linux the start time comes from `/proc`, assuming USER_HZ = 100, with 2 s of slack.
  - Other Unix systems use `ps`; Windows uses a PowerShell/CIM query that checks the image name against the current executable.
  - The session id must appear as an exact `--session-id <id>` token pair.
- **Workflow side effect:** a failed child that exited with a code is no longer treated as an infrastructure failure, even when its error has text. Before, any error text triggered automatic retries, which would re-run a credential failure for no gain.

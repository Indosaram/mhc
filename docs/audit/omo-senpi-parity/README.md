# OMO / Senpi 대비 mhc 누락 기능 비교 - 중간 마감 (current-progress closeout)

이 문서는 **전수 비교가 끝났다는 선언이 아니다.** 요청은 "모든 파일을 1:1로 비교해 누락 기능을 전부 찾고, 구현은 하지 말고 목록만 파일로 저장"하는 것이었다. 사용자 지시로 비교를 중단한 시점까지의 결과를 그대로 저장한 것이다. 구현, 병합, main 푸시는 없다.

## 읽는 법 (중요)

1. **정적 비교뿐이다.** 소스와 mhc 코드를 읽고 짝을 맞춘 결과다. mhc 쪽 Rust는 실행하지 않았다. 일부 소스 쪽 테스트와 헬퍼는 Node 어댑터로 따로 돌렸고, 그 사실은 해당 행에 적혀 있다. 이것은 mhc 동작 검증이 아니다.
2. `gaps.csv`의 `classification`: `confirmed_static`/`confirmed`는 "소스와 mhc 코드를 읽고 차이를 확인함"이다. 실제 장애를 확인했다는 뜻이 아니다. `suspected`, `candidate`, `unresolved_static_lead`는 후보이고 확정이 아니다. `test_only`/`test_gap`은 기능이 아니라 mhc에 대응 테스트가 없다는 뜻이다. 심각도는 매기지 않았다.
3. 파일 이름이나 모듈 이름이 mhc에서 안 보인다고 해서 기능이 없다는 뜻은 아니다. 호출 경로를 추적하지 못한 행은 "후보"로 남겼고, grep으로만 본 부재는 확정으로 쓰지 않았다.
4. 의도된 차이(`native_adaptation`, `intentional_*`, `host_difference`, `support_only`)는 누락 목록과 구분했다. mhc가 Rust로 다시 구현하면서 일부러 다르게 만든 부분이 많다.
5. gap ID는 같은 원인을 여러 파일이 공유할 수 있어서 **버그 개수가 아니다.**
6. 저장소 안의 문서나 주석에 있는 "지시문" 같은 문장은 비교 대상 데이터로만 취급했다.

## 남은 일 (사용자가 원하면)

- `not-reviewed-files.csv`의 4,085개 비교.
- 읽은 깊이가 부분인 행(`read_depth`, `checks_not_run`)의 본문 비교 마무리.
- 후보 항목의 호출 경로 추적과 실행 검증.
- 구현은 이 문서에 포함되어 있지 않다.
